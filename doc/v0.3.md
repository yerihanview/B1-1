# v0.3 — CSS 레이아웃과 반응형

## 1. 버전 목표

v0.2에서 만든 기본 시각 표현을 바탕으로 CSS 레이아웃 시스템을 적용하여 **모바일, 태블릿, 데스크톱 화면에 대응하는 반응형 페이지 구조**를 만든다.

이 버전의 핵심은 다음 흐름을 이해하는 것이다.

```text
HTML 구조
→ 기본 Normal Flow
→ Flexbox / Grid로 배치
→ 화면 크기 변화
→ Media Query 적용
→ 레이아웃 변화
```

v0.3이 끝나면 다음을 설명하고 직접 수정할 수 있어야 한다.

```text
왜 이 영역에 Flexbox를 사용하는가
왜 이 영역에 Grid를 사용하는가
화면이 좁아지거나 넓어질 때 무엇이 바뀌는가
Media Query가 어떤 CSS 규칙을 추가하거나 변경하는가
모바일 퍼스트 CSS가 어떤 방식으로 구성되는가
```

JavaScript를 이용한 햄버거 메뉴 동작이나 기타 사용자 인터랙션은 v0.4에서 구현한다.

---

## 2. 요구사항

### 2.1 기존 HTML과 CSS를 기반으로 작업

v0.1의 HTML 의미 구조와 v0.2의 기본 시각 표현을 유지한다.

기존 구조를 레이아웃 구현을 위해 불필요하게 다시 작성하지 않는다.

필요한 경우 레이아웃을 위한 class를 추가할 수 있다.

또한 이후 모바일 Navigation 동작에 사용할 햄버거 버튼의 HTML 구조가 아직 없다면 이 버전에서 추가할 수 있다.

단, 햄버거 버튼의 JavaScript 이벤트나 메뉴 열기/닫기 기능은 구현하지 않는다.

---

### 2.2 Normal Flow

Flexbox와 Grid를 사용하기 전에 HTML 요소가 CSS 레이아웃을 별도로 지정하지 않았을 때 기본적으로 어떻게 배치되는지 확인한다.

최소한 다음을 이해한다.

```text
block 요소
→ 기본적으로 위에서 아래로 배치

inline 성격의 요소
→ 가능한 범위에서 같은 줄에 배치
```

모든 요소에 Flexbox나 Grid를 적용하지 않는다.

기본 흐름으로 충분한 부분은 Normal Flow를 그대로 사용한다.

---

### 2.3 Flexbox

한 방향을 중심으로 요소를 배치하거나 정렬해야 하는 영역에 Flexbox를 사용한다.

대표적인 적용 대상은 Navigation이다.

필요에 따라 다음 영역에도 사용할 수 있다.

- Header 내부
- Hero 내부
- About 내부
- CTA 묶음
- Skills 목록
- Footer 내부

단, 모든 영역에 Flexbox를 적용하는 것을 목표로 하지 않는다.

각 영역에서 실제로 배치 문제가 있을 때 사용한다.

최소한 다음 개념과 속성을 이해한다.

```text
display: flex
flex-direction
justify-content
align-items
gap
flex-wrap
```

필요에 따라 다음 개념도 사용할 수 있다.

```text
flex-grow
flex-shrink
flex-basis
```

단, 현재 레이아웃에 실제로 필요하지 않다면 세부 flex 속성을 억지로 사용하지 않는다.

---

### 2.4 Navigation 레이아웃

큰 화면에서는 Header / Navigation이 다음과 같은 가로 구조를 가질 수 있도록 한다.

```text
Logo / Site Name
        ↔
Navigation Links
        ↔
Theme Toggle 영역
```

이 버전에서는 아직 Theme Toggle의 실제 기능을 만들지 않는다.

최종적으로 필요한 버튼이나 영역이 존재하는 경우 레이아웃상의 위치만 준비할 수 있다.

Navigation의 가로 정렬에는 Flexbox를 사용한다.

---

### 2.5 Grid

여러 개의 독립적인 콘텐츠를 행과 열로 배치할 필요가 있는 영역에 CSS Grid를 사용한다.

필수 적용 대상은 Projects 영역이다.

v0.1에서 만든 임시 Project `article`을 이용하여 여러 개의 임시 카드를 배치해 Grid 동작을 확인할 수 있다.

GitHub API 데이터는 아직 사용하지 않는다.

최소한 다음 개념과 속성을 이해한다.

```text
display: grid
grid-template-columns
gap
```

Projects의 반응형 카드 배치에는 다음을 사용한다.

```text
repeat()
auto-fit
minmax()
```

기본 형태는 다음 관계를 이해하는 것이 목적이다.

```text
사용 가능한 화면 폭
        ↓
들어갈 수 있는 카드 수 계산
        ↓
Grid column 수 변화
```

정확한 카드 최소 폭은 실제 디자인에 맞게 결정한다.

---

### 2.6 Flexbox와 Grid의 역할 구분

두 기술을 단순히 서로 대체 가능한 배치 도구로 이해하지 않는다.

이 프로젝트에서는 기본적으로 다음과 같이 구분한다.

```text
Flexbox
→ 한 방향 중심의 배치와 정렬

Grid
→ 행과 열을 가진 영역 배치
```

예:

```text
Navigation
→ Flexbox

Projects 카드 목록
→ Grid
```

실제 상황에 따라 다른 선택이 가능하다는 점은 이해하되, 이 버전에서는 위 구조를 기본 설계로 사용한다.

---

### 2.7 모바일 퍼스트

기본 CSS는 작은 화면을 기준으로 작성한다.

구조는 다음과 같다.

```text
기본 CSS
→ 모바일

@media (min-width: 768px)
→ 태블릿 이상에서 필요한 변경

@media (min-width: 1024px)
→ 데스크톱 이상에서 필요한 변경
```

모바일 스타일을 별도의 Media Query 안에 넣고 데스크톱을 기본값으로 만드는 방식은 사용하지 않는다.

---

### 2.8 Media Query

화면 폭에 따라 필요한 레이아웃 규칙을 변경한다.

기본 breakpoint는 다음을 사용한다.

```text
기본
→ 모바일

768px 이상
→ 태블릿

1024px 이상
→ 데스크톱
```

Media Query 안에서는 화면 크기에 따라 실제로 달라져야 하는 규칙만 작성한다.

동일한 CSS를 각 breakpoint마다 반복해서 작성하지 않는다.

---

### 2.9 반응형 Navigation 표현

모바일과 큰 화면에서 Navigation 표현을 다르게 한다.

기본 구조:

```text
모바일
→ 일반 Navigation 메뉴 숨김
→ 햄버거 버튼 표시

태블릿 / 데스크톱
→ 일반 Navigation 메뉴 표시
→ 햄버거 버튼 숨김
```

이 버전에서는 CSS에 의한 표시 상태만 구현한다.

햄버거 버튼을 눌렀을 때 메뉴가 열리고 닫히는 기능은 구현하지 않는다.

따라서 v0.3의 햄버거 버튼은 아직 **동작하지 않는 구조 및 반응형 UI 요소**다.

실제 사용자 click에 따른 메뉴 상태 변경은 v0.4에서 JavaScript로 구현한다.

---

### 2.10 Hero 반응형 레이아웃

Hero의 콘텐츠가 작은 화면과 큰 화면 모두에서 자연스럽게 읽히도록 배치한다.

모바일에서는 기본적으로 세로 흐름을 유지한다.

화면이 충분히 넓고 실제 디자인에 적합한 경우 태블릿 또는 데스크톱에서 Flexbox를 이용한 가로 배치를 사용할 수 있다.

예:

```text
모바일

Hero text
↓
CTA

태블릿 / 데스크톱

Hero text     다른 Hero 콘텐츠
```

Hero에 반드시 가로 레이아웃을 적용해야 하는 것은 아니다.

실제 콘텐츠 구조에 필요할 때만 적용한다.

---

### 2.11 About 반응형 레이아웃

프로필 이미지와 자기소개 콘텐츠를 화면 폭에 맞게 배치한다.

예:

```text
모바일

Profile Image
↓
Introduction

데스크톱

Profile Image | Introduction
```

필요한 경우 Flexbox를 사용할 수 있다.

화면이 좁을 때 콘텐츠가 지나치게 압축되지 않아야 한다.

---

### 2.12 Skills 반응형 표현

Skills 목록은 현재 콘텐츠에 맞는 단순한 반응형 구조를 사용한다.

필요하면 다음을 사용할 수 있다.

```text
Flexbox
flex-wrap
gap
```

또는 Normal Flow가 더 적절하다면 그대로 유지한다.

Skills를 반드시 복잡한 Grid로 만들 필요는 없다.

---

### 2.13 Projects 반응형 Grid

Projects 카드 영역은 CSS Grid를 사용한다.

화면 폭에 따라 카드 수가 자연스럽게 변화하도록 한다.

기본 구조 예:

```text
모바일
→ 좁은 화면에 맞는 카드 배치

화면이 넓어짐
→ 가능한 카드 수 증가
```

이를 위해 `auto-fit`과 `minmax()`를 사용한다.

특정 breakpoint마다 다음처럼 column 개수를 계속 직접 지정하는 것을 기본 방식으로 삼지 않는다.

```text
1열
→ 2열
→ 3열
```

대신 Grid가 사용 가능한 공간을 기준으로 가능한 열 개수를 계산하도록 한다.

Media Query는 Projects 이외의 전체 레이아웃 변경에도 사용한다.

---

### 2.14 Contact Form 반응형

Contact Form이 작은 화면에서 가로로 넘치지 않고 입력하기 편하도록 한다.

입력 요소는 사용 가능한 영역 안에서 자연스럽게 늘어나도록 한다.

필요하면 다음을 사용한다.

```text
width
max-width
```

폼의 유효성 검사나 오류 상태 UI는 아직 구현하지 않는다.

---

### 2.15 이미지 반응형 처리

프로필 이미지 등 콘텐츠 이미지가 컨테이너보다 크게 표시되어 레이아웃을 깨뜨리지 않도록 한다.

필요한 경우 다음과 같은 원리를 적용한다.

```text
이미지의 최대 폭
→ 부모 영역을 넘지 않음

원본 비율
→ 유지
```

정확한 CSS 값은 실제 구현에서 결정한다.

---

### 2.16 콘텐츠 최대 폭

큰 데스크톱 화면에서 콘텐츠가 화면 전체 폭으로 지나치게 늘어나지 않도록 필요한 영역에 `max-width`를 사용할 수 있다.

페이지의 주요 콘텐츠 폭과 좌우 여백이 일관되도록 공통 container 성격의 class를 사용할 수 있다.

단, 이 단계에서 별도의 복잡한 레이아웃 시스템이나 CSS 프레임워크를 만들지 않는다.

---

### 2.17 가로 스크롤 방지

모바일 화면에서 의도하지 않은 수평 스크롤이 발생하지 않도록 한다.

원인이 되는 요소를 직접 확인하고 수정한다.

단순히 문제를 숨기기 위해 모든 상황에서 다음과 같은 처리를 먼저 적용하지 않는다.

```css
overflow-x: hidden;
```

레이아웃이 화면 밖으로 벗어나는 실제 원인을 확인하는 것을 우선한다.

---

## 3. 목표 설계

v0.3 완료 시 전체 구조는 다음과 같다.

```text
HTML 의미 구조            ← v0.1
        ↓
기본 시각 표현            ← v0.2
        ↓
Normal Flow 이해
        ↓
Flexbox
        ├── Navigation
        ├── 필요한 1차원 배치
        └── 필요한 정렬
        ↓
Grid
        └── Projects
        ↓
모바일 퍼스트 CSS
        ↓
Media Query
        ├── 768px
        └── 1024px
        ↓
반응형 페이지
```

화면별 기본 상태는 다음과 같다.

```text
모바일
│
├── Header
│   ├── Site Name
│   ├── 일반 Navigation 숨김
│   └── Hamburger 표시
│
├── Hero
│   └── 작은 화면에 적합한 기본 배치
│
├── About
│   └── 세로 중심 배치
│
├── Skills
│   └── 화면 폭에 맞는 목록
│
├── Projects
│   └── 반응형 Grid
│
├── Contact
│   └── 화면 안에 맞는 Form
│
└── Footer

        ↓ 화면 확대

태블릿 / 데스크톱
│
├── Header
│   ├── Site Name
│   ├── Navigation 표시
│   └── Hamburger 숨김
│
├── Hero
│   └── 필요하면 넓은 화면용 배치
│
├── About
│   └── 필요하면 이미지 / 본문 가로 배치
│
├── Skills
│   └── 넓은 화면 활용
│
├── Projects
│   └── 사용 가능한 폭에 따라 Grid 열 증가
│
├── Contact
│   └── 적절한 최대 폭 유지
│
└── Footer
```

아직 JavaScript에 따른 화면 상태 변화는 없다.

## 4. 새롭게 배우는 개념

### 4.1 CSS Layout

CSS 레이아웃은 요소의 색이나 글자 모양을 정하는 것과 달리 **요소가 화면에서 어디에 배치되는가**를 다룬다는 것을 이해한다.

```text
v0.2
→ 요소가 어떻게 보이는가

v0.3
→ 요소가 어디에 어떻게 배치되는가
```

---

### 4.2 Normal Flow

브라우저가 별도의 레이아웃 시스템을 지정하지 않은 요소도 기본 규칙에 따라 배치한다는 것을 이해한다.

Flexbox와 Grid는 모든 요소에 반드시 적용해야 하는 기본값이 아니다.

---

### 4.3 Flex Container와 Flex Item

다음 관계를 이해한다.

```text
부모
display: flex
        ↓
Flex Container

직접 자식
        ↓
Flex Item
```

Flexbox 속성 일부는 부모에 적용되고 일부는 자식에 적용된다는 점을 이해한다.

---

### 4.4 Main Axis와 Cross Axis

Flexbox의 정렬을 단순히 좌우/상하로 암기하지 않는다.

`flex-direction`에 따라 기준 방향이 달라진다는 것을 이해한다.

```text
main axis
→ flex-direction이 결정하는 방향

cross axis
→ main axis와 교차하는 방향
```

이 개념을 통해 `justify-content`와 `align-items`의 역할을 이해한다.

---

### 4.5 justify-content와 align-items

다음 관계를 이해한다.

```text
justify-content
→ main axis 기준 정렬

align-items
→ cross axis 기준 정렬
```

속성값 전체를 암기하는 것이 아니라 현재 레이아웃에서 필요한 값을 읽고 수정할 수 있는 수준을 목표로 한다.

---

### 4.6 gap

Flexbox와 Grid에서 항목 사이의 간격을 부모 컨테이너에서 정의할 수 있음을 이해한다.

개별 자식 요소마다 임의의 margin을 반복하는 방식과 어떤 차이가 있는지 확인한다.

---

### 4.7 flex-wrap

한 줄에 모든 Flex Item을 배치할 공간이 없을 때 다음 줄로 이동시킬 수 있다는 것을 이해한다.

Skills 등에서 필요한 경우 사용한다.

---

### 4.8 CSS Grid

Grid가 행과 열을 기준으로 콘텐츠를 배치하는 레이아웃 시스템임을 이해한다.

다음 관계를 읽을 수 있어야 한다.

```text
Grid Container
        ↓
Grid Items
```

---

### 4.9 grid-template-columns

Grid에서 열 구조를 정의하는 역할을 이해한다.

다음과 같은 선언이 무엇을 결정하는지 설명할 수 있어야 한다.

```css
grid-template-columns: ...;
```

복잡한 Grid 기능 전체를 학습하지 않는다.

---

### 4.10 repeat()

동일하거나 반복되는 Grid 열 정의를 간결하게 표현할 수 있다는 것을 이해한다.

문법 자체보다 Projects Grid에서 어떤 역할을 하는지 파악한다.

---

### 4.11 minmax()

Grid 열이 가질 수 있는 최소 크기와 최대 크기의 범위를 정의한다는 것을 이해한다.

Projects 카드가 너무 좁아지는 것을 막으면서 남은 공간을 활용하는 방식과 연결해서 이해한다.

---

### 4.12 auto-fit

사용 가능한 공간에 들어갈 수 있는 만큼 Grid 열을 자동으로 구성한다는 기본 의미를 이해한다.

다음 관계를 설명할 수 있어야 한다.

```text
화면 폭 증가
→ 사용 가능한 공간 증가
→ 들어갈 수 있는 카드 수 증가
```

`auto-fit`과 `auto-fill`의 세부 차이를 이 버전의 필수 학습 범위로 확대하지 않는다.

---

### 4.13 Responsive Design

반응형 디자인은 단순히 화면을 줄이는 것이 아니라 **사용 가능한 화면 공간에 맞추어 콘텐츠의 배치와 크기를 조정하는 것**임을 이해한다.

---

### 4.14 Viewport

브라우저에서 현재 웹페이지가 표시되는 영역의 크기가 CSS 레이아웃 판단의 기준 중 하나라는 것을 이해한다.

Media Query와 연결해서 이해하는 정도로 다룬다.

---

### 4.15 Media Query

조건에 따라 특정 CSS 규칙을 적용할 수 있다는 것을 이해한다.

기본 구조:

```css
@media (min-width: ...) {
    ...
}
```

다음 흐름으로 이해한다.

```text
현재 viewport 확인
        ↓
조건 만족 여부
        ↓
Media Query 내부 CSS 적용 여부 결정
```

---

### 4.16 Breakpoint

Breakpoint가 특정 기기 모델을 구분하는 절대적인 경계가 아니라 **레이아웃을 변경할 기준점**이라는 것을 이해한다.

이 프로젝트에서는 설계 기준으로 다음 값을 사용한다.

```text
768px
1024px
```

현재 프로젝트에서는 이 값을 임의로 늘리거나 복잡한 breakpoint 체계를 추가하지 않는다.

---

### 4.17 Mobile First

작은 화면용 CSS를 기본값으로 작성하고 필요한 경우 더 넓은 화면에서 확장하는 방식임을 이해한다.

```text
기본 CSS
→ 작은 화면

min-width Media Query
→ 더 넓은 화면에서 변경
```

모바일 CSS와 데스크톱 CSS를 모두 별개의 완성본처럼 중복 작성하지 않는다.

---

### 4.18 Responsive Image

이미지가 고정 크기 때문에 부모 영역 밖으로 넘칠 수 있다는 점을 이해한다.

이미지 역시 화면 및 컨테이너 크기에 대응해야 한다는 것을 확인한다.

---

### 4.19 CSS에 의한 상태와 JavaScript 상태의 차이

현재 햄버거 버튼의 표시 여부는 viewport 조건에 따른 CSS 표현이다.

```text
화면 크기 변화
→ Media Query
→ Navigation / Hamburger 표시 상태 변경
```

아직 다음 흐름은 없다.

```text
사용자 click
→ JavaScript
→ menu 상태 변경
→ DOM class 변경
```

이 흐름은 v0.4에서 다룬다.

---

### 4.20 DevTools Responsive Mode

브라우저 DevTools의 반응형 화면 기능을 이용하여 다음을 확인한다.

```text
viewport 폭
모바일 화면
태블릿 화면
데스크톱 화면
Breakpoint 직전 / 직후
가로 스크롤 발생 여부
```

단순히 브라우저 창을 한 번 줄였다 늘리는 것만으로 검증을 끝내지 않는다.

## 5. 완료 / 검증 기준

### 5.1 Normal Flow

Flexbox와 Grid를 사용하지 않아도 되는 영역을 구분할 수 있다.

모든 부모 요소에 무분별하게 `display: flex` 또는 `display: grid`가 적용되어 있지 않다.

---

### 5.2 Navigation

큰 화면에서 Navigation이 Flexbox로 적절하게 배치된다.

모바일에서는 일반 메뉴와 햄버거 버튼의 표시 상태가 설계대로 전환된다.

햄버거 버튼을 클릭해도 메뉴가 열리지 않는 것은 현재 버전에서는 정상이다.

JavaScript menu toggle은 존재하지 않는다.

---

### 5.3 Flexbox

사용한 주요 Flexbox 영역에서 다음을 설명할 수 있다.

```text
어떤 요소가 Flex Container인가
어떤 요소가 Flex Item인가
main axis는 어느 방향인가
justify-content가 무엇을 하는가
align-items가 무엇을 하는가
```

---

### 5.4 Projects Grid

Projects의 카드 영역에 CSS Grid가 적용되어 있다.

다음 개념이 실제 코드에 연결되어 있다.

```text
grid-template-columns
repeat()
auto-fit
minmax()
gap
```

화면 폭이 변하면 가능한 범위 안에서 카드 열 수가 자연스럽게 달라진다.

GitHub API는 사용하지 않는다.

---

### 5.5 모바일 퍼스트

기본 CSS가 모바일 화면을 기준으로 동작한다.

태블릿과 데스크톱을 위한 변경 사항이 `min-width` 기반 Media Query로 추가된다.

---

### 5.6 Breakpoint

다음 기준이 존재한다.

```text
기본
→ 모바일

768px 이상
→ 태블릿

1024px 이상
→ 데스크톱
```

불필요한 breakpoint가 추가되어 있지 않다.

---

### 5.7 Hero / About / Skills

각 영역이 작은 화면에서 가로로 넘치지 않는다.

넓은 화면에서 레이아웃을 변경하도록 설계했다면 해당 breakpoint에서 정상적으로 변경된다.

Flexbox가 필요하지 않은 영역은 억지로 Flexbox로 만들지 않아도 된다.

---

### 5.8 Contact

Form이 모바일에서 viewport 밖으로 넘어가지 않는다.

입력 요소를 정상적으로 사용할 수 있다.

Validation이나 JavaScript 상태 표현은 존재하지 않는다.

---

### 5.9 이미지

프로필 이미지 등 주요 이미지가 작은 화면에서 컨테이너 밖으로 넘치지 않는다.

이미지 비율이 의도하지 않게 깨지지 않는다.

---

### 5.10 모바일 검증

DevTools Responsive Mode에서 작은 화면을 확인한다.

최소한 다음을 점검한다.

```text

텍스트를 읽을 수 있는가
Navigation 표시 상태가 올바른가
Hamburger 버튼이 보이는가
Hero가 화면 밖으로 벗어나지 않는가
About이 화면 밖으로 벗어나지 않는가
Projects 카드가 지나치게 좁아지지 않는가
Form을 사용할 수 있는가
```

---

### 5.11 태블릿 검증

768px 전후에서 다음을 확인한다.

```text
Media Query가 의도한 시점에 적용되는가
```

### 5.13 Breakpoint 경계 검증

정확히 고정된 세 화면만 확인하지 않는다.

```text
1024px
```

특정 크기에서만 우연히 정상적으로 보이는 레이아웃을 만들지 않는다.

임의의 Flexbox 영역과 Grid 영역을 선택하여 DevTools에서 레이아웃 구조를 확인한다.
