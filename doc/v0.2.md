# v0.2 — CSS 기본 표현

## 1. 버전 목표

v0.1에서 만든 HTML 구조에 CSS를 적용하여 웹사이트의 **기본적인 시각 표현**을 만든다.

이 버전의 핵심은 레이아웃을 만드는 것이 아니다.

먼저 다음 흐름을 이해한다.

```text
HTML 요소
→ CSS로 대상 선택
→ 스타일 규칙 적용
→ 브라우저가 계산
→ 화면 표현 변화
```

v0.2가 끝나면 색상, 글자, 크기, 간격, 테두리, 배경 등의 기본 스타일을 직접 읽고 수정할 수 있어야 한다.

Flexbox, Grid, 반응형 레이아웃은 v0.3에서 다룬다.

---

## 2. 요구사항

### 2.1 외부 스타일시트 사용

v0.1에서 연결한 다음 파일을 사용한다.

```text
css/style.css
```

HTML의 `style` 속성이나 `<style>` 태그를 기본 방식으로 사용하지 않는다.

스타일은 외부 CSS 파일에서 관리한다.

---

### 2.2 CSS 기본 구조

CSS 규칙의 기본 구조를 이해하고 사용한다.

```css
selector {
    property: value;
}
```

다음 관계를 이해한다.

```text
selector
→ 어떤 HTML 요소에 적용할 것인가

property
→ 무엇을 바꿀 것인가

value
→ 어떻게 바꿀 것인가
```

---

### 2.3 기본 선택자

최소한 다음 선택자의 의미와 차이를 이해한다.

```text
요소 선택자
class 선택자
id 선택자
```

실제 스타일링은 주로 요소 선택자와 class 선택자를 사용한다.

`id`는 페이지 내부 이동이나 특정 요소 식별 등의 역할을 우선하며, CSS에서 반드시 사용해야 하는 것은 아니다.

필요한 경우 v0.1 HTML에 스타일링을 위한 `class`를 추가할 수 있다.

단, CSS를 적용하기 위해 HTML의 의미 구조를 불필요하게 변경하지 않는다.

---

### 2.4 기본 CSS 변수

`:root`에 사이트에서 반복해서 사용하는 값을 CSS 변수로 정의한다.

최소한 **반복해서 사용하는 색상 값**은 CSS 변수로 관리한다.

예:

```css
:root {
    --color-background: ...;
    --color-text: ...;
    --color-primary: ...;
}
```

필요하면 폰트나 반복되는 간격 값도 변수로 둘 수 있다.

단, 이 단계에서 변수 체계나 디자인 시스템을 과도하게 설계하지 않는다.

정확한 변수 이름과 개수는 실제 디자인에 맞게 정한다.

다크 모드용 `[data-theme="dark"]` 변수는 v0.5에서 추가한다.

---

### 2.5 기본 색상

다음과 같은 기본 시각 요소에 색상을 적용한다.

- 페이지 배경
- 기본 글자
- 제목
- 링크
- CTA
- 카드
- Form 요소
- Footer

색상을 모든 요소에 직접 반복 작성하지 않고 필요한 경우 CSS 변수를 사용한다.

---

### 2.6 Typography

웹사이트의 기본 글자 표현을 정한다.

다음 요소의 차이가 화면에서 드러나도록 한다.

```text
본문
h1
section 제목
보조 텍스트
링크
버튼/CTA
```

최소한 다음 속성을 이해하고 필요에 따라 사용한다.

```text
font-family
font-size
font-weight
line-height
text-align
text-decoration
```

Google Fonts를 사용할지는 선택 사항이다.

외부 웹 폰트를 사용하더라도 CSS의 기본 동작을 이해하는 것이 우선이다.

---

### 2.7 Box Model

HTML 요소가 화면에서 차지하는 영역을 다음 구조로 이해한다.

```text
margin
└── border
    └── padding
        └── content
```

다음 속성을 실제 요소에 적용한다.

```text
width
max-width
margin
padding
border
```

필요한 경우 다음 기본 설정을 적용한다.

```css
box-sizing: border-box;
```

왜 사용하는지 설명할 수 있어야 한다.

---

### 2.8 기본 간격

섹션과 콘텐츠가 서로 붙어 있지 않도록 기본 간격을 설정한다.

예:

```text
section과 section 사이
제목과 본문 사이
리스트 항목 사이
폼 필드 사이
카드 내부
CTA 주변
```

이 단계의 목적은 정교한 레이아웃이 아니라 **콘텐츠의 구분이 보이도록 하는 것**이다.

Flexbox/Grid를 간격 조절 수단으로 사용하지 않는다.

---

### 2.9 기본 크기와 단위

CSS 값에서 최소한 다음 단위의 의미를 구분한다.

```text
px
%
rem
```

필요하면 `em`이 존재한다는 정도까지 확인한다.

모든 CSS 단위를 암기하는 것이 목표는 아니다.

현재 프로젝트에서 왜 특정 단위를 선택했는지 설명할 수 있는 수준을 목표로 한다.

---

### 2.10 기본 테두리와 형태

필요한 요소에 다음 표현을 적용할 수 있다.

```text
border
border-radius
background
```

예:

- CTA
- Project 임시 카드
- Form 입력 요소
- 프로필 이미지

이 단계에서는 복잡한 장식 효과를 만들지 않는다.

---

### 2.11 Project 카드 기본 표현

v0.1에서 만든 임시 `article`을 카드처럼 구분되도록 기본 스타일을 적용한다.

최소한 다음을 사용할 수 있다.

```text
background
padding
border 또는 box-shadow
border-radius
```

카드들을 여러 열로 배치하지 않는다.

Projects Grid는 v0.3에서 구현한다.

---

### 2.12 Form 기본 표현

다음 요소가 서로 구분되고 사용할 수 있도록 기본 스타일을 적용한다.

```text
label
input
textarea
button
```

입력 필드의 크기, 글자, padding, border 등의 기본 표현을 정한다.

Form validation 상태 표현은 아직 구현하지 않는다.

---

### 2.13 hover와 transition

사용자가 마우스를 올렸을 때 상호작용 가능한 요소임을 알 수 있도록 기본적인 `:hover` 스타일을 적용한다.

주요 대상은 다음과 같다.

- 링크
- CTA
- 버튼

Project 카드 전체에 hover 효과를 적용하는 것은 선택 사항이다.

카드 자체가 클릭 가능한 요소가 아니라면 불필요한 hover 효과로 상호작용 가능하다는 잘못된 인상을 주지 않도록 한다.

변화가 지나치게 갑작스럽지 않도록 필요한 곳에 `transition`을 적용한다.

이 단계에서는 JavaScript 이벤트를 사용하지 않는다.

```text
:hover
→ CSS가 상태를 감지
→ CSS 표현 변화
```

라는 흐름만 다룬다.

---

## 3. 목표 설계

v0.2 완료 시 구조는 다음과 같다.

```text
HTML 의미 구조        ← v0.1
        ↓
CSS 선택자
        ↓
기본 스타일 규칙
        ↓
CSS 변수
        ↓
색상 / Typography
        ↓
Box Model / 간격
        ↓
테두리 / 배경 / 그림자
        ↓
hover / transition
```

화면은 다음 수준까지 표현한다.

```text
페이지 전체 배경과 기본 글자 스타일
│
├── Header / Navigation 기본 표현
│
├── Hero
│   ├── 제목과 설명의 시각적 계층
│   └── CTA 기본 스타일
│
├── About
│   ├── 이미지 기본 표현
│   └── 본문 스타일
│
├── Skills
│   └── 목록 기본 표현
│
├── Projects
│   └── 단일 카드 기본 표현
│
├── Contact
│   └── Form 기본 표현
│
└── Footer 기본 표현
```

아직 다음과 같은 배치는 만들지 않는다.

```text
Navigation 좌우 배치
Projects 여러 열 배치
Hero 가로 배치
모바일 / 태블릿 / 데스크톱 전환
```

이들은 v0.3의 책임이다.

## 4. 새롭게 배우는 개념

### 4.1 CSS의 역할

HTML과 CSS의 역할 차이를 다시 확인한다.

```text
HTML
→ 무엇이 있는가 / 어떤 의미인가

CSS
→ 그것이 어떻게 보이는가
```

CSS가 HTML 구조를 대신하지 않는다는 것을 이해한다.

---

### 4.2 CSS Rule

다음 구조를 읽을 수 있어야 한다.

```css
.project-card {
    padding: 1rem;
}
```

이를 다음과 같이 해석할 수 있어야 한다.

```text
.project-card라는 class를 가진 요소를 선택해서
padding을 1rem으로 설정한다.
```

---

### 4.3 선택자

다음 차이를 이해한다.

```css
p { }
.card { }
#projects { }
```

```text
p
→ 해당 HTML 요소

.card
→ 해당 class를 가진 요소

#projects
→ 해당 id를 가진 요소
```

특히 실제 스타일링에서는 class를 주요 연결점으로 사용하는 이유를 이해한다.

`id` 선택자의 존재와 동작은 이해하되, 이를 스타일링에 반드시 사용할 필요는 없다.

---

### 4.4 Cascade

하나의 요소에 여러 CSS 규칙이 적용될 수 있음을 이해한다.

브라우저는 규칙이 겹칠 때 어떤 스타일을 실제로 적용할지 결정한다.

이 버전에서는 cascade의 전체 알고리즘을 암기하지 않는다.

최소한 다음 사실을 이해한다.

```text
같은 요소에 여러 규칙이 적용될 수 있다.
→ 어떤 규칙이 실제로 적용되는지 결정 과정이 존재한다.
```

스타일이 예상대로 적용되지 않을 때 DevTools에서 이를 확인할 수 있어야 한다.

---

### 4.5 Specificity

선택자의 종류에 따라 우선순위가 달라질 수 있음을 이해한다.

이 버전에서는 specificity 계산 공식을 암기하지 않는다.

다음 정도를 이해하는 것이 목표다.

```text
요소 선택자
class 선택자
id 선택자

→ 같은 속성을 충돌해서 지정하면
  선택 방식에 따라 결과가 달라질 수 있다.
```

`!important`로 문제를 해결하는 습관을 만들지 않는다.

---

### 4.6 Inheritance

일부 CSS 속성은 부모 요소의 값을 자식이 물려받는다는 것을 이해한다.

대표적으로 글자 관련 스타일을 통해 확인한다.

예:

```css
body {
    font-family: ...;
    color: ...;
}
```

모든 속성이 상속되는 것은 아니라는 것까지 이해한다.

---

### 4.7 Box Model

모든 요소가 기본적으로 다음 영역을 가진다는 것을 이해한다.

```text
content
padding
border
margin
```

특히 다음 차이를 설명할 수 있어야 한다.

```text
padding
→ 요소 내부 여백

margin
→ 요소 바깥 여백
```

---

### 4.8 box-sizing

기본 `content-box` 방식과 `border-box`의 차이를 필요한 수준까지 이해한다.

`border-box`를 사용하면 지정한 크기를 계산하기 쉬워지는 이유를 설명할 수 있어야 한다.

---

### 4.9 CSS 단위

다음 단위를 구분한다.

```text
px
→ 고정적인 CSS 픽셀 단위

%
→ 기준 요소에 대한 비율

rem
→ root 글자 크기를 기준으로 하는 상대 단위
```

이 버전에서는 단위 체계 전체를 학습하지 않는다.

---

### 4.10 CSS Custom Properties

다음 구조를 이해한다.

```css
:root {
    --color-primary: ...;
}

a {
    color: var(--color-primary);
}
```

CSS 변수를 사용하는 목적은 단순히 코드를 짧게 쓰기 위해서가 아니라 **반복되는 디자인 값을 한곳에서 관리하기 위해서**라는 것을 이해한다.

이 단계에서는 반복되는 색상을 중심으로 사용한다.

폰트나 간격 값까지 변수화할지는 실제 반복 여부에 따라 결정한다.

이 개념은 이후 v0.5의 다크 모드에서 다시 사용한다.

---

### 4.11 Pseudo-class

`:hover`처럼 요소의 특정 상태를 선택할 수 있음을 이해한다.

```css
a:hover {
    ...
}
```

JavaScript 이벤트와 구분한다.

```text
CSS :hover
→ CSS가 표현 상태를 바꿈

JavaScript event
→ 프로그램 로직이 사용자 행동에 반응
```

JavaScript 이벤트는 v0.4에서 배운다.

---

### 4.12 Transition

CSS 속성이 한 값에서 다른 값으로 변할 때 중간 변화를 표현할 수 있다는 것을 이해한다.

다음 관계만 우선 이해한다.

```text
기본 상태
→ hover
→ 속성값 변경

transition
→ 그 변경 과정을 부드럽게 표현
```

복잡한 animation은 다루지 않는다.

---

### 4.13 DevTools의 Styles 확인

브라우저 개발자 도구를 이용해 다음을 확인한다.

```text
선택된 HTML 요소
적용된 CSS 규칙
덮어써진 CSS 규칙
계산된 스타일
Box Model
```

CSS 문제를 AI에게 바로 수정시키기 전에 어떤 규칙이 적용되고 있는지 직접 확인하는 습관을 만든다.

---

## 5. 완료 / 검증 기준

### 5.1 외부 CSS

모든 기본 스타일이 `css/style.css`에서 관리된다.

HTML에 불필요한 inline style이 없다.

---

### 5.2 CSS 변수

`:root`에 반복해서 사용하는 색상이 CSS 변수로 정의되어 있다.

실제 스타일에서 `var()`로 사용된다.

폰트나 간격 변수는 실제로 반복 관리할 필요가 있을 때만 추가한다.

다크 모드 변수는 아직 존재하지 않아도 된다.

---

### 5.3 기본 시각 계층

CSS가 적용된 화면에서 다음 차이를 시각적으로 구분할 수 있다.

- 페이지 제목
- section 제목
- 본문
- 보조 텍스트
- 링크
- CTA

---

### 5.4 Box Model

주요 section과 콘텐츠에 적절한 margin/padding이 적용되어 서로 구분된다.

DevTools에서 특정 요소의 content, padding, border, margin 영역을 확인할 수 있다.

---

### 5.5 Projects

임시 Project article이 카드 형태로 시각적으로 구분된다.

`box-shadow` 또는 border 등으로 카드 영역을 확인할 수 있다.

여러 열 Grid는 아직 사용하지 않는다.

---

### 5.6 Contact

label, input, textarea, button이 시각적으로 구분되고 입력하기 어렵지 않은 기본 크기를 가진다.

validation 상태 스타일은 없다.

---

### 5.7 Hover / Transition

링크, CTA, 버튼 등 실제 상호작용 가능한 요소에서 적절한 hover 변화를 확인할 수 있다.

필요한 변화에는 transition이 적용되어 있다.

Project 카드 hover는 최종 디자인에서 필요할 경우에만 적용한다.

JavaScript는 사용하지 않는다.

---

### 5.8 레이아웃 제한

다음 기술이 아직 사용되지 않았음을 확인한다.

```text
display: flex
display: grid
@media
```

v0.2를 구현하기 위해 이를 우회적으로 선행 사용하지 않는다.

---

### 5.9 브라우저 확인

Live Server에서 다음을 확인한다.

