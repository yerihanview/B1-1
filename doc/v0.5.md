# v0.5 — 다크 모드와 상태 유지

## 1. 버전 목표

v0.4에서 구현한 기본 DOM 인터랙션 위에 **명시적인 상태가 화면을 결정하고, 그 상태가 브라우저에 저장되는 구조**를 처음 구현한다.

이 버전의 핵심 흐름은 다음과 같다.

```text
사용자 click
        ↓
theme 상태 변경
        ↓
DOM의 theme 속성 변경
        ↓
CSS 변수 변경
        ↓
화면 theme 변경
        ↓
localStorage 저장
```

페이지를 다시 열거나 새로고침할 때는 저장된 값을 먼저 복원한다.

```text
페이지 시작
        ↓
localStorage 확인
        ↓
저장된 theme가 있으면 복원
        ↓
DOM theme 적용
        ↓
화면 theme 결정
```

v0.5가 끝나면 최소한 다음 관계를 설명할 수 있어야 한다.

```text
현재 theme 상태는 무엇인가
→ 상태는 어디에서 결정되는가
→ DOM의 무엇이 바뀌는가
→ CSS가 왜 다른 색상을 사용하는가
→ localStorage에는 무엇을 저장하는가
→ 새로고침 후 어떻게 이전 상태를 복원하는가
```

이번 버전에서는 사용자의 직접 선택만 다룬다.

시스템 테마 감지와 OS 테마 변경 실시간 반영은 v1.3에서 다룬다.

---

## 2. 요구사항

### 2.1 기존 구조를 기반으로 작업

v0.4까지 완성한 HTML, CSS, JavaScript 구조와 기존 인터랙션을 유지한다.

다크 모드 구현을 위해 기존 구조를 불필요하게 다시 작성하지 않는다.

필요하면 Theme Toggle을 식별하기 위한 class 또는 JavaScript용 선택자를 추가할 수 있다.

기존 햄버거 메뉴, 내부 스크롤, Scroll-to-Top, Navigation scroll 동작은 그대로 유지한다.

---

### 2.2 Light / Dark Theme

웹사이트는 최소한 다음 두 테마를 가진다.

```text
light
dark
```

기본 화면은 light theme로 시작할 수 있다.

단, `localStorage`에 사용자가 이전에 선택한 theme가 있다면 해당 값을 우선하여 복원한다.

이 버전에서는 시스템 설정을 기본값으로 사용하지 않는다.

---

### 2.3 CSS 변수 재사용

v0.2에서 정의한 CSS 변수를 다크 모드에 확장하여 사용한다.

기본 구조는 다음과 같다.

```css
:root {
    /* light theme variables */
}

[data-theme="dark"] {
    /* dark theme variables */
}
```

light와 dark에서 달라지는 대표적인 값은 CSS 변수로 관리한다.

예:

```text
페이지 배경
기본 글자색
카드 배경
border 또는 구분선 색상
Navigation 배경
버튼 또는 강조 색상
```

각 요소에 dark mode 색상을 직접 반복해서 작성하는 방식은 기본 구현으로 사용하지 않는다.

핵심은 다음 구조다.

```text
DOM theme 속성 변경
        ↓
적용되는 CSS 변수 집합 변경
        ↓
기존 CSS가 같은 var()를 사용
        ↓
화면 전체 theme 변경
```

---

### 2.4 `[data-theme="dark"]`

다크 모드는 DOM의 특정 요소에 `data-theme="dark"` 속성이 존재하는 상태로 표현한다.

적용 대상은 프로젝트 구조에 맞게 결정하되, 페이지 전체 theme를 제어할 수 있는 상위 요소를 사용한다.

예:

```text
<html data-theme="dark">
```

또는 이에 준하는 상위 요소를 사용할 수 있다.

핵심은 JavaScript가 각 요소의 색상을 직접 바꾸는 것이 아니라 **DOM의 theme 속성 하나를 변경하고 CSS가 화면 표현을 담당하게 하는 것**이다.

---

### 2.5 Theme Toggle

Header / Navigation에 준비된 Theme Toggle을 실제로 동작하게 만든다.

기본 흐름:

```text
Theme Toggle click
        ↓
현재 theme 확인
        ↓
light ↔ dark 변경
        ↓
DOM theme 속성 변경
        ↓
화면 변경
```

이벤트는 `addEventListener()`를 사용한다.

HTML의 inline event handler는 사용하지 않는다.

---

### 2.6 현재 theme 상태

JavaScript에서 현재 theme가 `light`인지 `dark`인지 판단할 수 있어야 한다.

상태는 다음 질문에 답할 수 있는 형태로 관리한다.

```text
지금 화면에 적용되어야 하는 theme는 무엇인가?
```

필요하다면 변수로 현재 theme를 관리할 수 있다.

예:

```text
let currentTheme = ...
```

단, 이 버전의 목적을 넘어서는 별도 상태 관리 객체나 상태 관리 라이브러리는 사용하지 않는다.

중요한 것은 상태값과 DOM 표현이 서로 어긋나지 않도록 하는 것이다.

---

### 2.7 DOM 속성 변경

JavaScript에서 theme 상태에 따라 DOM의 `data-theme` 속성을 추가하거나 변경한다.

이번 버전에서 새롭게 이해할 핵심은 **class뿐 아니라 HTML attribute도 DOM 상태를 표현하는 데 사용할 수 있다는 점**이다.

기본 관계:

```text
theme 상태
        ↓
DOM data-theme 속성
        ↓
CSS selector
        ↓
CSS 변수
        ↓
화면
```

정확한 DOM API는 구현 과정에서 확인한다.

---

### 2.8 `localStorage` 저장

사용자가 Theme Toggle로 theme를 직접 변경하면 해당 값을 `localStorage`에 저장한다.

저장 대상은 최소한 다음 정도로 제한한다.

```text
theme: light 또는 dark
```

불필요한 UI 상태를 함께 저장하지 않는다.

핵심 흐름:

```text
사용자 theme 선택
        ↓
현재 theme 변경
        ↓
DOM 적용
        ↓
localStorage 저장
```

---

### 2.9 페이지 시작 시 theme 복원

페이지가 시작될 때 `localStorage`에서 저장된 theme 값을 확인한다.

기본 흐름:

```text
페이지 시작
        ↓
localStorage theme 확인
        ↓
저장값 있음
→ 해당 theme 적용

저장값 없음
→ 기본 light theme 사용
```

저장값이 없다는 이유만으로 시스템의 `prefers-color-scheme`을 확인하지 않는다.

시스템 theme는 v1.3의 범위다.

---

### 2.10 저장값과 DOM 상태의 일치

Theme Toggle을 여러 번 사용하거나 페이지를 새로고침해도 다음 세 값이 서로 모순되지 않아야 한다.

```text
현재 JavaScript theme 상태
DOM의 data-theme 값
localStorage의 theme 값
```

사용자 동작 후에는 모두 같은 theme를 가리켜야 한다.

---

### 2.11 기존 인터랙션과의 공존

다크 모드를 추가해도 v0.4의 기능이 계속 정상 동작해야 한다.

확인 대상:

```text
Hamburger menu
Navigation link
부드러운 내부 스크롤
Scroll-to-Top
Navigation scroll style
```

다크 모드 때문에 기존 `.active`, `.scrolled` 등 다른 UI 상태가 깨지지 않아야 한다.

---

### 2.12 Theme Toggle의 기본 사용성

Theme Toggle이 사용자가 누를 수 있는 실제 control임이 HTML 의미상 드러나야 한다.

현재 구조가 버튼이라면 기존 버튼 구조를 유지한다.

필요한 경우 화면에 현재 theme 또는 전환 대상이 이해되도록 텍스트, 아이콘, 접근성용 이름을 정리할 수 있다.

단, 이번 버전의 학습 범위를 Theme Toggle 디자인이나 아이콘 시스템으로 확대하지 않는다.

---

## 3. 목표 설계

v0.5 완료 시 구조는 다음과 같다.

```text
HTML 구조                    ← v0.1
        ↓
CSS 기본 표현                ← v0.2
        ↓
반응형 레이아웃              ← v0.3
        ↓
DOM / Event                  ← v0.4
        ↓
Theme State
        │
        ├── light
        └── dark
        ↓
DOM data-theme
        ↓
CSS theme variables
        ↓
화면 theme
        ↓
localStorage
```

사용자 동작:

```text
Theme Toggle click
        ↓
현재 theme 확인
        ↓
다음 theme 결정
        ↓
DOM data-theme 변경
        ↓
화면 변경
        ↓
localStorage 저장
```

페이지 시작:

```text
페이지 로드
        ↓
localStorage 확인
        ↓
저장값 있음
→ 저장된 theme 적용

저장값 없음
→ light theme 적용
```

이 버전의 핵심 차이는 v0.4와 다음처럼 구분된다.

```text
v0.4
Event
→ DOM class 변경
→ 즉시 화면 변화

v0.5
Event
→ 명시적인 theme 상태 결정
→ DOM attribute 변경
→ 화면 변화
→ 상태 저장
→ 다음 실행에서 상태 복원
```

## 4. 새롭게 배우는 개념

### 4.1 상태(State)

상태는 현재 화면이나 동작을 결정하는 값이라는 수준에서 이해한다.

현재 프로젝트의 예:

```text
theme = light
또는
theme = dark
```

이 값에 따라 화면이 달라진다.

핵심 관계:

```text
상태가 바뀜
→ DOM 표현이 바뀜
→ 화면이 바뀜
```

상태 관리 이론 전체를 학습하지 않는다.

---

### 4.2 v0.4의 UI 상태와 v0.5의 명시적 상태

v0.4에서는 다음처럼 class 자체가 UI 상태를 표현했다.

```text
active 있음
→ 메뉴 열림

active 없음
→ 메뉴 닫힘
```

v0.5에서는 이를 한 단계 확장하여 JavaScript가 `light` / `dark`라는 상태값을 명시적으로 판단하고 그 상태를 DOM과 저장소에 연결한다.

```text
theme 상태
→ DOM attribute
→ CSS
→ 화면
→ localStorage
```

---

### 4.3 `data-*` Attribute

HTML 요소에 사용자 정의 데이터를 표현할 수 있는 `data-*` 속성이 존재함을 이해한다.

이번 프로젝트에서는 다음처럼 theme 상태를 표현한다.

```text
data-theme="dark"
```

CSS는 이를 selector로 사용할 수 있다.

```css
[data-theme="dark"] {
    ...
}
```

`data-*` 전체 기능을 학습 범위로 확대하지 않는다.

---

### 4.4 DOM Attribute 변경

JavaScript가 DOM 요소의 attribute 값을 읽거나 변경할 수 있음을 이해한다.

핵심은 구체적인 메서드 암기가 아니라 다음 흐름이다.

```text
JavaScript theme 값
        ↓
DOM attribute 변경
        ↓
CSS selector 상태 변경
```

---

### 4.5 상태와 CSS 변수의 연결

CSS 변수는 v0.2에서 반복되는 디자인 값을 관리하기 위해 사용했다.

v0.5에서는 같은 변수를 theme별로 다른 값으로 정의한다.

```text
light theme
→ --color-background: 밝은 값

 dark theme
→ --color-background: 어두운 값
```

각 요소는 여전히 다음처럼 같은 변수를 사용한다.

```text
background: var(--color-background)
```

따라서 theme가 바뀔 때 요소별 CSS를 다시 작성하지 않아도 된다.

---

### 4.6 `localStorage`

`localStorage`는 브라우저가 같은 사이트에서 사용할 값을 저장할 수 있는 공간이라는 수준에서 이해한다.

이번 버전에서는 theme 하나만 저장한다.

핵심 특징:

```text
페이지 새로고침
→ 값 유지

브라우저에서 다시 페이지 열기
→ 저장된 값 사용 가능
```

서버 데이터베이스나 사용자 계정과 연결된 저장 방식은 아니다.

---

### 4.7 저장과 복원의 차이

두 동작을 구분한다.

```text
저장
→ 사용자가 theme를 바꾼 결과를 localStorage에 기록

복원
→ 페이지 시작 시 이전 기록을 읽어 현재 theme로 적용
```

단순히 값을 저장하는 것만으로는 상태 유지가 완성되지 않는다.

페이지 시작 시 읽어서 다시 적용해야 한다.

---

### 4.8 초기 상태 결정

페이지가 시작될 때 theme를 어떤 값으로 둘지 결정해야 한다.

v0.5의 우선순위는 단순하다.

```text
저장된 사용자 theme 있음
→ 저장값 사용

저장값 없음
→ light 사용
```

시스템 theme는 아직 입력값으로 사용하지 않는다.

---

### 4.9 상태의 단일 의미 유지

현재 theme를 여러 곳에서 서로 다른 값으로 임의 관리하지 않는다.

다음 질문을 항상 연결해서 본다.

```text
현재 theme는 무엇인가?
DOM에는 무엇이 적용되어 있는가?
localStorage에는 무엇이 저장되어 있는가?
```

사용자 동작 이후 이 값들이 서로 일치해야 한다.

---

### 4.10 브라우저 저장소 확인

DevTools에서 `localStorage`에 저장된 값을 직접 확인할 수 있어야 한다.

최소한 다음을 확인한다.

```text
theme key가 존재하는가
값이 light 또는 dark인가
Theme Toggle 후 값이 바뀌는가
새로고침 후 값이 유지되는가
```

브라우저 저장소 전체 API 학습으로 확대하지 않는다.

---

## 5. 완료 / 검증 기준

### 5.1 Light / Dark Theme

Theme Toggle을 이용해 light와 dark를 전환할 수 있다.

두 theme에서 기본 콘텐츠를 읽고 사용할 수 있다.

---

### 5.2 CSS 변수

light와 dark에서 달라지는 주요 디자인 값이 CSS 변수로 관리된다.

다크 모드를 위해 각 요소에 동일한 색상 규칙이 과도하게 중복되어 있지 않다.

---

### 5.3 `[data-theme="dark"]`

DOM의 theme attribute가 CSS의 dark theme 변수와 연결되어 있다.

JavaScript가 각 요소의 색상을 직접 반복 변경하지 않는다.

---

### 5.4 Theme Toggle 이벤트

Theme Toggle의 click event가 `addEventListener()`로 연결되어 있다.

inline event handler를 사용하지 않는다.

---

### 5.5 상태 변경

Theme Toggle click 시 현재 theme가 다음 값으로 변경된다.

```text
light → dark
dark → light
```

현재 theme를 어떤 코드가 결정하는지 설명할 수 있다.

---

### 5.6 DOM 변경

상태 변경 후 DOM의 `data-theme` 값이 현재 theme와 일치한다.

CSS가 해당 attribute를 기준으로 화면을 변경한다.

---

### 5.7 localStorage 저장

Theme Toggle을 누르면 현재 theme가 `localStorage`에 저장된다.

DevTools에서 저장값을 직접 확인할 수 있다.

---

### 5.8 새로고침 후 복원

예:

```text
dark 선택
→ 새로고침
→ dark 유지
```

반대 방향도 정상 동작한다.

---

### 5.9 저장값이 없는 경우

`localStorage`에 theme 값이 없는 상태에서 페이지를 열면 기본 light theme로 정상 표시된다.

이 상태에서 시스템 theme 자동 감지는 수행하지 않는다.

---

### 5.10 기존 기능 회귀 확인

다크 모드를 추가한 후에도 다음 v0.4 기능이 정상 동작한다.

```text
Hamburger menu
Navigation / CTA 내부 이동
부드러운 스크롤
Scroll-to-Top 표시 / click
Navigation scroll style
```

---

### 5.11 모바일 / 데스크톱 확인

모바일과 데스크톱에서 모두 Theme Toggle을 사용할 수 있다.

다크 모드 때문에 Navigation 또는 다른 레이아웃이 깨지지 않는다.

---

### 5.12 Console 확인

Theme Toggle 사용, 새로고침, 기존 인터랙션 사용 과정에서 현재 구현 때문에 발생하는 JavaScript 오류가 없어야 한다.

---

### 5.13 DevTools 저장소 확인

## 7. VS Code AI 작업 Task

각 Task 완료 후 반드시 다음 절차를 따른다.

```text
diff 확인
→ 코드 확인
→ 브라우저 확인
→ 이해 확인
```

---

### Task 1 — 기존 Theme Toggle과 CSS 변수 구조 확인

새 기능을 바로 구현하지 않는다.

먼저 현재 HTML / CSS에서 다음을 확인한다.

```text
Theme Toggle 요소가 존재하는가
어떤 selector로 선택할 수 있는가
:root에 어떤 색상 변수가 있는가
light theme에서 반복되는 색상 값이 변수로 연결되어 있는가
```

Theme Toggle 구조가 없다면 현재 Header / Navigation 구조에 맞는 최소한의 버튼만 추가한다.

아직 click 동작이나 `localStorage`는 구현하지 않는다.

확인할 개념:

- 기존 DOM 구조
- CSS custom property
- `:root`
- Theme Toggle의 HTML 의미
- 현재 버전이 v0.4 위에 추가되는 방식

---

### Task 2 — Dark Theme CSS 변수 추가

`[data-theme="dark"]`에서 dark theme용 CSS 변수 값을 정의한다.

아직 JavaScript로 전환하지 않는다.

DevTools에서 `data-theme="dark"`를 임시로 적용하거나 제거하여 CSS만으로 theme 표현이 바뀌는지 확인할 수 있다.

확인할 개념:

- attribute selector
- `data-theme`
- 같은 CSS 변수 이름의 값 재정의
- CSS 변수와 실제 요소 스타일의 연결

이번 Task에서는 `localStorage`를 사용하지 않는다.

---

### Task 3 — Theme Toggle click과 DOM theme 변경

Theme Toggle 요소를 JavaScript에서 선택하고 click event를 연결한다.

흐름:

```text
Theme Toggle 선택
        ↓
click listener
        ↓
현재 theme 확인
        ↓
다음 theme 결정
        ↓
DOM data-theme 변경
```

아직 저장과 복원은 구현하지 않는다.

확인할 개념:

- `querySelector`
- `addEventListener`
- click
- current theme
- 상태 변경
- DOM attribute 변경
- 상태 → DOM → CSS → 화면

---

### Task 4 — localStorage에 theme 저장

사용자가 Theme Toggle로 theme를 변경했을 때 현재 값을 `localStorage`에 저장한다.

저장은 theme 하나만 대상으로 한다.

흐름:

```text
Theme Toggle click
→ theme 변경
→ DOM 적용
→ localStorage 저장
```

DevTools에서 저장값을 직접 확인한다.

확인할 개념:

- browser storage
- key / value
- 저장
- DevTools Application / Storage 확인

아직 페이지 시작 시 자동 복원은 다음 Task에서 구현한다.

---

### Task 5 — 페이지 시작 시 theme 복원

JavaScript가 실행될 때 `localStorage`의 theme 값을 읽는다.

흐름:

```text
페이지 시작
→ 저장된 theme 확인

있음
→ 해당 theme 적용

없음
→ light 적용
```

확인할 개념:

- 초기 상태
- 저장값 읽기
- 저장과 복원의 차이
- 초기 상태 → DOM 적용

시스템 theme는 확인하지 않는다.

---

### Task 6 — Theme 상태 일치와 반복 동작 검증

새 기능을 추가하지 않는다.

다음을 반복해서 확인한다.

```text
light → dark
dark → light
여러 번 Toggle
새로고침
저장값 삭제 후 다시 로드
```

각 상황에서 다음이 일치하는지 확인한다.

```text
현재 화면 theme
DOM data-theme
localStorage theme
```

필요하다면 중복되거나 서로 어긋난 theme 처리 코드만 정리한다.

새로운 추상화나 별도 상태 관리 구조를 추가하지 않는다.

---

### Task 7 — 기존 기능 회귀 및 전체 검증

새 기능은 추가하지 않는다.

다음을 검토한다.

```text
Theme Toggle이 addEventListener로 동작하는가
light / dark 전환이 정상인가
CSS 변수로 theme가 바뀌는가
JavaScript가 요소별 색상을 직접 반복 변경하지 않는가
localStorage에 theme가 저장되는가
새로고침 후 복원되는가
저장값이 없을 때 light로 시작하는가
시스템 theme를 선행 감지하지 않는가
OS theme 변경 listener가 없는가
Hamburger가 정상 동작하는가
Navigation / CTA 이동이 정상인가
Scroll-to-Top이 정상인가
Navigation scroll style이 정상인가
Console 오류가 없는가
모바일 / 데스크톱에서 화면이 깨지지 않는가
Form validation을 선행 구현하지 않았는가
GitHub API를 선행 구현하지 않았는가
```

DevTools에서 DOM attribute와 `localStorage` 값도 직접 확인한다.
