# v1.1 — Hero 타이핑 효과

## 1. 버전 목표

v1.0에서 외부 제출 가능한 상태로 확정한 B1-1 기본 결과를 유지한 채, Hero 영역의 소개 문구 일부에 **한 글자씩 순서대로 나타나는 타이핑 효과**를 추가한다.

v1.1은 `v1.0` 이후의 첫 번째 확장 버전이다.

이 버전의 핵심은 시각 효과 자체가 아니라 **시간의 흐름에 따라 JavaScript 상태가 변하고, 그 상태가 DOM 텍스트를 반복적으로 갱신하는 구조**를 이해하는 것이다.

핵심 흐름은 다음과 같다.

```text
페이지 시작
        ↓
Hero 타이핑 대상 확인
        ↓
전체 문자열 준비
        ↓
현재 글자 위치 확인
        ↓
현재 위치까지의 문자열 결정
        ↓
textContent 변경
        ↓
setTimeout으로 다음 실행 예약
        ↓
현재 글자 위치 증가
        ↓
종료 조건 확인
        ↓
전체 문자열 표시 후 종료
```

v1.1이 끝나면 최소한 다음 관계를 설명할 수 있어야 한다.

```text
타이핑할 전체 문자열은 어디에서 오는가
→ 현재 글자 위치는 무엇을 의미하는가
→ 문자열에서 현재 표시할 부분을 어떻게 결정하는가
→ textContent는 어떤 DOM을 바꾸는가
→ setTimeout은 무엇을 예약하는가
→ 함수가 왜 다시 호출되는가
→ 어떤 조건에서 반복 호출이 끝나는가
→ 최종적으로 전체 문장이 왜 한 번만 완성되는가
```

이번 버전에서는 단순한 타이핑 효과 한 가지에 집중한다.

다음과 같은 복잡한 타자기 애니메이션으로 확대하지 않는다.

```text
여러 문구 순환
문자 삭제 효과
무한 반복
커서 깜빡임을 위한 별도 애니메이션 시스템
타이핑 속도 랜덤화
외부 animation / typing 라이브러리
```

## 2. 요구사항

### 2.1 v1.0 완료 상태를 기반으로 작업

v1.0에서 확정한 전체 기능을 유지한다.

최소한 다음 기존 기능이 그대로 동작해야 한다.

```text
Header / Navigation
Hero
About
Skills
Projects
Contact
Footer

Responsive layout
Hamburger menu
Smooth internal scroll
Scroll-to-Top
Navigation scroll style

Light / Dark theme
localStorage theme restore

Contact Form validation

GitHub API
loading / success / error / API empty
403 rate limit error
Retry
Projects dynamic rendering
Project filter
Filter empty

Intersection Observer reveal
GitHub Pages deployment
README / screenshots
```

타이핑 효과를 추가하기 위해 기존 v1.0 기능을 다시 설계하거나 대규모 리팩터링하지 않는다.

특히 다음 구조는 그대로 유지한다.

```text
Projects
API → 원본 repositories → filter() → map() → DOM

Theme
사용자 선택 → data-theme → CSS variables → localStorage

Contact
submit / input → validation → 오류 / 성공 UI
```

v1.1의 수정 범위는 기본적으로 **Hero의 타이핑 대상과 이를 제어하는 작은 JavaScript 로직**에 한정한다.

---

### 2.2 Hero 기존 의미 구조 유지

v1.0 Hero의 다음 콘텐츠와 역할을 유지한다.

```text
인사말
이름 또는 자기소개 핵심 문구
짧은 소개
CTA
```

타이핑 효과를 적용하기 위해 Hero 전체 HTML을 다시 작성하지 않는다.

타이핑 대상이 기존 텍스트의 일부라면 필요한 최소 범위에서 요소 또는 class를 식별 가능하게 정리한다.

예시 개념:

```text
Hero 소개 문장
└── 타이핑 대상 텍스트 요소
```

정확한 HTML 태그와 class 이름은 현재 v1.0 코드 구조에 맞춰 결정한다.

---

### 2.3 타이핑 대상은 Hero 문구 일부로 제한

타이핑 효과는 Hero 전체 콘텐츠가 아니라 **지정된 소개 문구 일부**에 적용한다.

예:

```text
Frontend Developer
```

화면에서는 다음처럼 점진적으로 나타난다.

```text
F
Fr
Fro
Fron
Front
...
Frontend Developer
```

타이핑할 실제 문구는 현재 포트폴리오 내용에 맞게 결정한다.

B1-1 원문과 `extended-design.md`는 특정 문구를 고정하지 않는다.

따라서 임의의 예제 문구를 최종 콘텐츠로 강제하지 않는다.

---

### 2.4 JavaScript가 없어도 Hero의 핵심 내용 유지

타이핑 효과는 보조적인 시각 효과다.

따라서 JavaScript가 실행되지 않더라도 Hero의 핵심 소개 내용을 사용자가 이해할 수 있는 기존 구조를 유지한다.

기본 설계 원칙은 다음과 같다.

```text
HTML
→ 의미 있는 최종 문구를 가지고 있음

JavaScript 실행
→ 해당 문구를 타이핑 효과의 입력 문자열로 사용
→ 화면 표현을 한 글자씩 다시 구성

JavaScript 실행 실패
→ HTML의 원래 핵심 문구는 남아 있음
```

타이핑 효과를 만들기 위해 HTML의 핵심 문구 자체를 비워 둔 채 JavaScript에만 의존하는 구조를 기본 방식으로 삼지 않는다.

---

### 2.5 전체 문자열

타이핑 효과에는 최종적으로 표시할 **전체 문자열**이 필요하다.

개념:

```text
fullText
→ 최종적으로 화면에 완성될 문장
```

문자열은 기존 Hero 텍스트에서 읽거나 현재 코드 구조에 맞는 단순한 방식으로 준비할 수 있다.

중요한 것은 다음을 설명할 수 있는 것이다.

```text
전체 문장은 무엇인가?
현재 화면에는 그중 어디까지 표시되어 있는가?
```

이 버전에서 텍스트 목록이나 여러 문구 배열을 만들 필요는 없다.

---

### 2.6 현재 글자 위치 상태

한 글자씩 출력하려면 현재 어느 위치까지 처리했는지를 나타내는 값이 필요하다.

개념 예:

```text
currentIndex
```

의미:

```text
0
→ 아직 첫 글자 처리 전 또는 시작 위치

1
→ 첫 글자까지 처리

2
→ 두 글자까지 처리

...

전체 문자열 길이
→ 모든 글자 처리 완료
```

정확한 변수 이름은 현재 코드 스타일에 맞게 결정한다.

핵심은 숫자 값 자체보다 **현재 출력 진행 상태를 나타내는 값**이라는 점이다.

---

### 2.7 문자열과 인덱스

JavaScript 문자열은 문자들의 순서를 가진 데이터라는 수준에서 이해한다.

이번 버전에서는 현재 글자 위치를 이용하여 다음 중 하나의 읽기 쉬운 방식으로 현재 표시 문자열을 결정한다.

```text
현재 글자 하나를 추가
```

또는

```text
전체 문자열의 시작부터 현재 위치까지 일부를 추출
```

정확한 문자열 API는 실제 구현 코드에서 확인한다.

문자열 메서드 전체를 학습 범위로 확대하지 않는다.

핵심 관계는 다음이다.

```text
전체 문자열
+
현재 인덱스
        ↓
현재 화면에 표시할 문자열
```

---

### 2.8 `textContent`로 DOM 텍스트 변경

타이핑 대상의 현재 표시 문구는 JavaScript에서 `textContent`를 이용하여 갱신한다.

기본 흐름:

```text
현재 표시할 문자열 결정
        ↓
타이핑 대상 DOM 요소
        ↓
textContent 변경
        ↓
화면의 글자 수 증가
```

이번 기능은 텍스트 자체를 변경하는 것이므로 복잡한 HTML 문자열을 생성할 필요가 없다.

`innerHTML`을 사용해야 할 특별한 이유를 만들지 않는다.

v0.7의 Project 카드 렌더링처럼 HTML 구조를 생성하는 기능과 구분한다.

```text
Project cards
→ 여러 HTML 구조 생성 가능

Hero typing
→ 기존 한 요소의 텍스트 내용 변경
```

---

### 2.9 `setTimeout`

한 번에 모든 글자를 표시하지 않고 일정 시간이 지난 뒤 다음 글자를 처리하도록 `setTimeout`을 사용한다.

기본 관계:

```text
현재 글자 표시
        ↓
setTimeout
        ↓
일정 시간 뒤 다음 타이핑 함수 실행
```

`setTimeout`은 코드 전체를 멈추게 하는 기능으로 이해하지 않는다.

이번 버전에서는 최소한 다음 정도를 이해한다.

```text
지금 당장 다음 글자를 처리하지 않고
일정 시간이 지난 뒤 실행할 작업을 예약한다.
```

타이머 API 전체나 JavaScript 이벤트 루프의 세부 이론으로 학습 범위를 확대하지 않는다.

---

### 2.10 타이핑 함수의 반복 호출

타이핑 함수는 한 번 실행될 때 현재 단계의 텍스트를 갱신하고, 아직 끝나지 않았다면 `setTimeout`을 이용해 **자기 다음 실행을 예약**한다.

개념 흐름:

```text
typeText()
        ↓
현재 index 확인
        ↓
현재 문자열 표시
        ↓
index 증가
        ↓
아직 남은 글자 있음
→ setTimeout(typeText, ...)
        ↓
다음 실행
```

이 구조는 일반적인 반복문과 완전히 같은 실행 방식으로 보지 않는다.

핵심 차이는 다음이다.

```text
일반 반복
→ 같은 실행 흐름 안에서 연속 처리

v1.1 타이핑
→ 한 번 처리
→ 시간 지연
→ 다음 실행 예약
```

재귀 이론 전체를 별도 학습 주제로 확대하지 않는다.

현재 함수가 왜 다시 실행되는지만 이해하면 된다.

---

### 2.11 종료 조건

전체 문자열을 모두 표시한 뒤에는 다음 실행을 예약하지 않는다.

기본 흐름:

```text
현재 index
        ↓
전체 문자열 길이와 비교
        ↓
아직 남은 글자 있음
→ 다음 실행 예약

모든 글자 완료
→ 추가 setTimeout 없음
→ 최종 문자열 유지
```

종료 조건이 없으면 불필요한 반복 호출이 계속될 수 있으므로 반드시 명확하게 둔다.

v1.1의 기본 완료 상태는 다음이다.

```text
페이지 로드
→ 한 번 타이핑
→ 전체 문장 완성
→ 종료
```

---

### 2.12 타이핑 속도

각 글자 사이의 시간 간격은 구현 단계에서 결정한다.

B1-1 원문과 `extended-design.md`는 특정 millisecond 값을 고정하지 않는다.

따라서 실제 Hero 문구의 길이와 읽기 경험을 보고 단순한 고정값 하나를 사용한다.

개념:

```text
typingDelay
→ 다음 글자 처리를 예약할 시간 간격
```

이번 버전에서는 다음으로 확대하지 않는다.

```text
글자별 랜덤 속도
문장 부호별 다른 속도
사용자 설정 속도
복잡한 easing
```

---

### 2.13 페이지 시작 시 타이핑 시작

v1.1의 타이핑 효과는 별도의 사용자 클릭이 필요한 기능이 아니다.

페이지가 로드되어 기존 `defer` JavaScript가 실행될 때 타이핑 로직을 시작한다.

개념:

```text
HTML 파싱
        ↓
defer script 실행
        ↓
Hero target 선택 가능
        ↓
타이핑 초기 상태 준비
        ↓
type function 시작
```

v0.1부터 유지해 온 외부 JavaScript와 `defer` 구조를 불필요하게 변경하지 않는다.

별도의 새로운 script 파일이 꼭 필요한 기능도 아니다.

현재 프로젝트 규모와 기존 JavaScript 구조에 맞춰 최소 수정한다.

---

### 2.14 타이핑 대상이 없을 때 기존 기능 보호

현재 코드 구조에서 타이핑 대상 DOM을 찾지 못한 경우, 타이핑 효과 하나 때문에 다른 v1.0 JavaScript 기능 전체가 중단되는 구조를 피한다.

기본 원칙:

```text
타이핑 대상 확인
        ↓
대상 존재
→ 타이핑 시작

대상 없음
→ 타이핑 로직 실행하지 않음
→ 기존 v1.0 기능은 계속 동작
```

복잡한 오류 처리 시스템을 만들 필요는 없다.

확장 기능이 기존 완료 기능을 깨뜨리지 않도록 하는 최소 방어가 목적이다.

---

### 2.15 반응형 레이아웃 유지

타이핑 효과는 텍스트 표시 방식만 변경하며 v0.3 / v1.0의 반응형 Hero 레이아웃을 다시 설계하지 않는다.

최소 다음 화면에서 확인한다.

```text
모바일
태블릿
데스크톱
```

특히 글자가 늘어나는 과정에서 다음 문제가 없어야 한다.

```text
Hero 높이 또는 주변 배치가 비정상적으로 흔들림
긴 문구가 화면 밖으로 넘침
의도하지 않은 가로 스크롤
CTA 위치가 사용할 수 없을 정도로 이동
```

필요하다면 현재 Hero 문구나 기존 CSS 안에서 최소한의 조정만 한다.

새로운 반응형 시스템을 만들지 않는다.

---

### 2.16 Light / Dark Theme와 독립

타이핑 효과는 theme 상태와 별개의 기능이다.

```text
Theme
→ data-theme / CSS variables

Typing
→ 문자열 / index / textContent / timer
```

두 상태를 하나의 JavaScript 상태로 합치지 않는다.

Light / Dark theme 모두에서 타이핑 문구를 읽을 수 있어야 한다.

Theme Toggle을 눌러도 타이핑 기능 때문에 theme가 초기화되거나 `localStorage` 값이 바뀌어서는 안 된다.

---

### 2.17 기존 Intersection Observer와 독립

v0.9의 Intersection Observer는 특정 콘텐츠의 viewport 진입을 감지하는 기능이다.

v1.1 타이핑 효과는 페이지 시작 후 시간 흐름에 따라 Hero 텍스트를 변경하는 기능이다.

두 기능의 책임을 구분한다.

```text
Intersection Observer
→ viewport 진입 감지

Hero typing
→ 시간에 따른 문자 출력
```

타이핑 시작 조건을 새롭게 Intersection Observer에 연결하지 않는다.

Hero가 화면에 들어올 때마다 다시 타이핑되는 기능도 만들지 않는다.

---

### 2.18 외부 라이브러리 사용 금지

타이핑 효과를 위해 외부 typing / animation 라이브러리를 추가하지 않는다.

이 버전의 학습 목적은 다음 JavaScript 흐름을 직접 경험하는 것이다.

```text
문자열
→ index
→ textContent
→ setTimeout
→ 반복 호출
→ 종료 조건
```

따라서 순수 JavaScript로 구현한다.

---

### 2.19 v1.0 배포 상태 유지

v1.1 구현 후에도 기존 GitHub Pages 사이트에서 전체 기능이 정상 동작해야 한다.

로컬 확인만으로 버전 완료로 판단하지 않는다.

현재 Git workflow에 따라 v1.1 변경을 repository에 반영하고 배포된 URL에서 최소한 다음을 다시 확인한다.

```text
Hero typing
Hero CTA
Navigation
Theme Toggle
Projects
Contact
```

v1.0에서 만든 README 전체를 다시 작성하지 않는다.

필요한 경우 현재 프로젝트의 버전 또는 기능 설명에 타이핑 효과가 추가되었음을 최소 범위에서 반영한다.

## 4. 새롭게 배우는 개념

### 4.1 문자열(String)

문자열은 글자들이 순서를 가지고 있는 값이라는 수준에서 이해한다.

예:

```text
Frontend Developer
```

이번 버전에서는 문자열 전체 기능을 학습하지 않는다.

타이핑 효과에서 필요한 질문에 답할 수 있으면 된다.

```text
전체 문자열은 무엇인가?
문자열 길이는 얼마인가?
현재 위치까지 어떤 글자를 보여야 하는가?
```

---

### 4.2 인덱스(Index)

인덱스는 문자열 안의 특정 위치를 가리키는 숫자라는 수준에서 이해한다.

이번 기능에서는 인덱스를 **타이핑 진행 상태**와 연결한다.

```text
현재 index가 작음
→ 일부 글자만 표시

index가 증가
→ 더 많은 글자 표시

마지막 위치 도달
→ 전체 문장 표시
```

배열과 문자열의 인덱스 이론 전체로 확대하지 않는다.

---

### 4.3 문자열 길이

전체 문자열의 길이는 타이핑이 끝났는지 판단하는 기준으로 사용할 수 있다.

기본 관계:

```text
현재 위치
<
전체 문자열 길이
→ 아직 처리할 글자 있음

현재 위치가 완료 조건 충족
→ 종료
```

정확한 비교 방식은 실제 코드에서 확인한다.

---

### 4.4 문자열 일부 추출 또는 누적

현재 화면에는 전체 문자열이 아니라 현재 진행 위치까지의 문자열만 보이게 해야 한다.

이를 구현하는 방식은 단순하고 읽기 쉬운 방법을 사용한다.

개념적으로는 다음 두 구조 중 하나다.

```text
A. 현재 글자를 기존 표시 문자열 뒤에 추가
```

또는

```text
B. 전체 문자열의 시작부터 현재 위치까지 잘라서 표시
```

이 버전에서는 둘을 모두 구현하지 않는다.

현재 코드가 어떤 방식을 사용하는지 설명할 수 있으면 된다.

---

### 4.5 `textContent`

`textContent`는 DOM 요소의 텍스트 내용을 읽거나 바꿀 수 있다는 수준에서 이해한다.

이번 기능에서는 다음 목적에 사용한다.

```text
Hero target element
        ↓
textContent
        ↓
현재 표시할 문자열로 변경
```

HTML 구조를 새로 만드는 것이 아니라 **기존 요소의 텍스트만 바꾸는 상황**에 적합하다는 점을 확인한다.

---

### 4.6 시간 기반 실행

v1.1 이전의 주요 JavaScript 기능은 주로 다음 입력에 반응했다.

```text
click
scroll
submit
input
API response
viewport intersection
```

v1.1에서는 새로운 입력 축이 추가된다.

```text
시간 경과
```

즉 사용자가 계속 클릭하지 않아도 일정 시간 후 다음 코드가 실행될 수 있다는 것을 경험한다.

---

### 4.7 `setTimeout`

`setTimeout`은 일정 시간이 지난 뒤 실행할 함수를 예약하는 기능이라는 수준에서 이해한다.

핵심 흐름:

```text
현재 함수 실행
→ setTimeout으로 다음 함수 실행 예약
→ 현재 함수 종료
→ 일정 시간 경과
→ 예약된 함수 실행
```

다음처럼 이해하지 않는다.

```text
setTimeout
→ JavaScript 전체를 그 시간 동안 멈춤
```

이벤트 루프, call stack, task queue의 상세 내부 동작은 이번 버전의 필수 학습 범위가 아니다.

---

### 4.8 반복 호출

타이핑 함수는 스스로 다음 실행을 예약함으로써 여러 번 실행된다.

```text
1회 실행
→ 한 단계 진행
→ 다음 실행 예약

2회 실행
→ 한 단계 진행
→ 다음 실행 예약

...
```

중요한 것은 함수 이름이나 재귀 용어 암기가 아니라 다음 관계다.

```text
왜 한 번의 함수 실행만으로 전체 문장을 표시하지 않는가?
왜 다음 실행을 예약해야 하는가?
```

---

### 4.9 종료 조건

반복되는 동작은 언제 끝나야 하는지 명확해야 한다.

v1.1에서는 다음 질문으로 이해한다.

```text
아직 표시하지 않은 글자가 남아 있는가?
```

남아 있으면 다음 실행을 예약하고, 없으면 종료한다.

이 조건을 통해 다음을 방지한다.

```text
필요 없는 timeout 계속 생성
완료 후에도 같은 DOM 변경 반복
의도하지 않은 무한 동작
```

---

### 4.10 상태와 렌더링의 연결

v1.1에서도 기존 프로젝트의 핵심 학습 원칙인 **상태 → 화면 변화**를 유지한다.

이번 상태는 다음처럼 볼 수 있다.

```text
전체 문자열
현재 글자 위치
현재 표시 문자열
```

그 결과:

```text
currentIndex 변경
        ↓
현재 표시 문자열 변경
        ↓
textContent 변경
        ↓
Hero 화면 변경
```

따라서 타이핑 효과를 단순 CSS 장식이 아니라 JavaScript 상태가 DOM을 결정하는 기능으로 이해한다.

---

### 4.11 사용자 이벤트와 시간 기반 실행의 차이

기존 기능과 비교하여 구분한다.

```text
Theme Toggle
사용자 click
→ 즉시 theme 변경

Form
사용자 submit / input
→ validation 실행

Typing
시간 경과
→ 예약된 함수 실행
→ 다음 글자 표시
```

모두 JavaScript가 DOM을 변경하지만 **실행을 시작시키는 조건이 다르다.**

---

### 4.12 기존 DOM 선택 개념 재사용

v0.4에서 배운 `querySelector()` 등의 DOM 선택 개념을 그대로 재사용한다.

새롭게 DOM API 전체를 공부하지 않는다.

이번 기능에서는 다음 관계만 확인하면 된다.

```text
Hero typing target 선택
→ 해당 요소의 textContent 읽기 / 변경
```

---

### 4.13 기존 `const` / `let` 개념 재사용

v0.4에서 배운 변수 선언 원칙을 유지한다.

예상되는 역할:

```text
변하지 않는 DOM 참조 / 전체 문자열 / 속도 값
→ const 후보

계속 증가하는 현재 index
→ let 후보
```

실제 코드에서 왜 특정 값이 `const`이고 다른 값이 `let`인지 설명할 수 있어야 한다.

---

### 4.14 DevTools / 코드 확인

타이핑 효과는 빠르게 지나갈 수 있으므로 브라우저 결과만 보고 이해했다고 판단하지 않는다.

코드에서 직접 다음 위치를 찾는다.

```text
타이핑 대상 선택
전체 문자열 결정
현재 index 선언
textContent 변경
setTimeout 호출
index 변경
종료 조건
```

필요하면 DevTools Console의 오류 여부도 확인한다.

이번 버전에서는 타이머 내부 상태를 추적하기 위한 복잡한 디버깅 도구 사용을 필수화하지 않는다.

## 5. 완료 / 검증 기준

### 5.1 타이핑 효과 동작

페이지를 새로 열거나 새로고침하면 Hero의 지정 문구가 한 글자씩 순서대로 나타난다.

최종적으로 전체 문장이 정확하게 표시된다.

---

### 5.2 글자 순서

문자는 원래 문자열의 순서를 유지한다.

다음 문제가 없어야 한다.

```text
글자 누락
순서 뒤바뀜
중복 글자
최종 문장 불일치
```

---

### 5.3 종료 조건

전체 문장이 완성되면 추가 타이핑이 계속되지 않는다.

기본 완료 상태:

```text
한 번 타이핑
→ 전체 문장 완성
→ 종료
```

무한 반복이나 자동 삭제가 없어야 한다.

---

### 5.4 `setTimeout` 실제 사용

시간 간격을 둔 반복 실행에 `setTimeout`이 실제 기능 안에서 사용된다.

타이핑 효과를 CSS animation만으로 대체하지 않는다.

---

### 5.5 `textContent` 실제 사용

Hero 타이핑 대상의 화면 텍스트 갱신에 `textContent`를 실제로 사용한다.

불필요한 HTML 문자열 생성으로 기능을 복잡하게 만들지 않는다.

---

### 5.6 문자열 / index 상태 설명 가능

다음 질문에 답할 수 있어야 한다.

```text
전체 문자열은 어떤 값인가?

index가 증가하면 화면에서 무엇이 바뀌는가?
전체 문자열 길이는 어디에서 종료 조건과 연결되는가?
```

---

### 5.7 반복 호출 흐름 설명 가능

```text
- 한 번에 한 단계씩 textContent 갱신
- current index 증가
- 아직 남은 글자가 있을 때만 setTimeout으로 같은 타이핑 함수를 다시 실행
- 전체 문자열이 완성되면 추가 timeout 예약 없이 종료
```

```text
새 기능을 추가하지 말고 현재 구현을 v1.1.md 완료 기준과 대조해줘.

Hero 타이핑은 한 문자열을 페이지 로드 후 한 번 출력하고 종료해야 한다.

기존 v1.0 기능이 유지되어야 하고, v1.2 실제 Form 전송이나 v1.3 시스템 theme 기능은 없어야 한다.

배포 환경에서 문제가 발견된 경우 그 문제만 최소 수정해줘.
불필요한 리팩터링은 하지 마.
```

#### Diff 확인

```text
최종 검증 과정에서 불필요한 코드 변경이 생기지 않았는가
v1.2 / v1.3 기능이 들어오지 않았는가
```

#### 코드 확인

```text
Hero typing target

current index
typing delay
textContent 변경
type function
setTimeout
index 증가
종료 조건
최초 시작
```

#### 브라우저 확인

로컬뿐 아니라 배포 URL에서 확인한다.

```text
새로고침
→ 타이핑 시작
→ 전체 문장 완성
→ 기존 페이지 정상 사용
```

#### 이해 확인

다음 질문에 답할 수 있으면 v1.1을 완료한다.

```text
1. 타이핑 전체 문자열은 어디에서 오는가?
2. 현재 index는 무엇을 의미하는가?
3. textContent는 언제 바뀌는가?
4. setTimeout은 무엇을 예약하는가?
5. 함수는 왜 여러 번 실행되는가?
6. 종료 조건은 무엇인가?
7. 왜 전체 문장이 완성된 뒤 반복이 멈추는가?
8. 이 기능이 기존 v1.0 상태들과 어떻게 독립되어 있는가?
```

## 8. v1.1 완료 후 상태

v1.1이 완료되면 프로젝트는 다음 상태다.

```text
v1.0
B1-1 필수 요구사항 전체
+ Project filtering
+ GitHub Pages 배포
+ 최종 검증

        ↓

v1.1
Hero typing effect 추가
```

새롭게 추가된 학습 흐름은 다음이다.

```text
전체 문자열
        ↓
현재 글자 위치
        ↓
현재 표시 문자열
        ↓
textContent
        ↓
Hero DOM 변화
        ↓
setTimeout
        ↓
다음 실행
        ↓
종료 조건
```

즉 v1.1은 기존 B1-1의 이벤트 / 상태 / 비동기 흐름 위에 **시간 기반 DOM 변경**을 추가한 확장 단계다.

다음 버전 경계는 그대로 유지한다.

```text
v1.2
→ 실제 Contact Form 전송

v1.3
→ 시스템 다크 모드 감지
→ 실행 중 OS theme 변경 실시간 반영
```

v1.1 완료 시점에도 위 기능들은 존재하지 않아야 한다.
