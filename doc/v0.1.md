# v0.1 — HTML 구조

## 1. 버전 목표

B1-1 최종 웹사이트의 전체 콘텐츠 구조를 HTML로 먼저 만든다.

이 버전에서는 화면을 좋게 만드는 것이 목적이 아니다.

목표는 다음과 같다.

```text
웹사이트에 어떤 정보가 존재하는가
→ 그 정보들은 어떤 의미 관계를 가지는가
→ HTML 문서에서 어떤 구조로 표현할 것인가
```

v0.1이 끝나면 이후 CSS와 JavaScript가 붙을 수 있는 **안정적인 HTML 골격**이 존재해야 한다.

---

## 2. 요구사항

### 2.1 프로젝트 기본 구성

다음과 같은 기본 파일 구조를 만든다.

```text
/
├── index.html
├── css/
│   └── style.css
├── js/
│   └── main.js
└── images/
    └── ...
```

`index.html`에서 외부 CSS와 JavaScript 파일을 연결한다.

JavaScript는 다음 버전에서 DOM을 다룰 수 있도록 `defer` 방식으로 연결한다.

이 버전에서는 CSS와 JavaScript 파일에 실제 기능을 구현하지 않는다.

VS Code에서 Live Server를 사용하여 `index.html`을 실행하고, 파일을 수정했을 때 브라우저에 변경 내용이 반영되는 개발 환경을 확인한다.

---

### 2.2 전체 HTML 구조

페이지의 큰 구조는 다음과 같이 설계한다.

```text
body
├── header
│   └── nav
│
├── main
│   ├── Hero section
│   ├── About section
│   ├── Skills section
│   ├── Projects section
│   └── Contact section
│
└── footer
```

HTML 요소는 단순히 화면 모양이 아니라 **콘텐츠가 가진 의미와 역할**을 기준으로 선택한다.

---

### 2.3 Header / Navigation

`header` 안에 사이트의 주요 이동을 담당하는 `nav`를 만든다.
내비게이션에는 최소한 다음 섹션으로 이동할 수 있는 링크를 둔다.

```text
About
Skills
Projects
Contact
```

각 링크는 해당 섹션의 `id`와 연결한다.

예:

```text
href="#projects"
        ↓
id="projects"
```

이 단계에서는 햄버거 메뉴나 부드러운 스크롤 기능을 구현하지 않는다.

---

### 2.4 Hero

Hero는 방문자가 처음 보는 소개 영역이다.

최소한 다음 내용을 포함한다.

- 인사말
- 이름 또는 자기소개 핵심 문구
- 짧은 소개 문장
- Projects 이동 CTA
- Contact 이동 CTA

CTA가 페이지 내부의 다른 위치로 **이동하는 역할**이라면 `button`보다 `a` 요소를 사용하는 것이 의미상 적절하다.

따라서 Projects와 Contact CTA는 각 section으로 이동하는 앵커 링크로 구성한다.

버튼처럼 보이게 만드는 시각적 표현은 CSS 단계에서 구현한다.

---

### 2.5 About

About에는 최소한 다음 내용을 포함한다.

- 자기소개
- 프로필 이미지
- 관심 분야 또는 개발자로서의 소개

프로필 이미지는 `images/` 디렉터리에 두고 `img` 요소로 표시한다.

이미지에는 의미 있는 `alt` 텍스트를 작성한다.

---

### 2.6 Skills

Skills는 기술 스택을 표현한다.

기술 목록이라는 의미가 드러나도록 리스트 구조를 사용한다.

예:

```text
Skills
├── HTML
├── CSS
└── JavaScript
```

현재 가지고 있는 기술을 과장해서 채우기보다 실제 소개할 내용을 사용한다.

이 버전에서는 기술별 아이콘이나 시각적 카드 스타일을 구현하지 않는다.

---

### 2.7 Projects

Projects는 이후 GitHub API에서 가져온 repository가 표시될 영역이다.

v0.1에서는 아직 GitHub API를 호출하지 않는다.

대신 다음 구조만 준비한다.

```text
Projects section
└── 프로젝트 목록 영역
    └── 임시 project article
```

프로젝트 하나가 독립적인 콘텐츠 단위라는 의미를 확인하기 위해 임시 프로젝트 항목에는 `article`을 사용한다.

임시 프로젝트에는 구조 확인에 필요한 최소한의 데이터를 둔다.

예:

```text
프로젝트 이름
프로젝트 설명
사용 언어
저장소 링크
```

이 임시 데이터는 v0.7에서 GitHub API 기반 동적 렌더링으로 교체한다.

따라서 v0.1에서 프로젝트 카드의 최종 디자인이나 동적 생성 방식은 결정하지 않는다.

---

### 2.8 Contact

Contact에는 문의 폼의 HTML 구조를 만든다.

최소 입력 항목은 다음과 같다.

- 이름
- 이메일
- 메시지
- 제출 버튼

각 입력 요소에는 대응하는 `label`을 둔다.

폼의 의미에 맞는 입력 타입을 사용한다.

예:

```text
이름      → text
이메일    → email
메시지    → textarea
```

이 버전에서는 HTML 폼의 구조와 각 요소의 의미에 집중한다.

`required`를 포함한 validation 관련 설계는 v0.6에서 JavaScript validation 흐름과 함께 결정한다.

JavaScript를 이용한 validation 로직과 실제 서버 전송은 이 버전에서는 구현하지 않는다.

---

### 2.9 Footer

Footer에는 최소한 다음 정보를 둔다.

- 저작권 또는 이름
- GitHub 링크
- 필요하면 LinkedIn 등 외부 프로필 링크

사이트의 주요 콘텐츠가 아니라 문서 전체에 대한 부가 정보를 담는 영역으로 사용한다.

---


## 4. 새롭게 배우는 개념

### 4.1 HTML 문서 구조

다음 요소의 역할을 구분할 수 있어야 한다.

```text
<!DOCTYPE html>
html
head
body
```

특히 `head`와 화면에 표시되는 `body`의 역할 차이를 이해한다.

---

### 4.2 요소, 속성, 중첩

HTML 문서는 요소가 단순하게 나열된 문자열이 아니라 부모와 자식 관계를 가진 구조라는 것을 이해한다.

예:

```text
main
└── section
    └── article
```

요소에 추가 정보를 부여하는 속성의 역할도 이해한다.

예:

```text
href
src
alt
id
class
type
name
for
```

이 구조가 이후 JavaScript의 DOM 트리 이해로 연결된다는 것까지 파악한다.

DOM 조작 자체는 아직 배우지 않는다.

---

### 4.3 외부 파일 연결

HTML과 CSS / JavaScript가 서로 다른 파일이어도 브라우저가 연결해서 사용할 수 있다는 것을 이해한다.

```text
index.html
    ├── css/style.css
    └── js/main.js
```

JavaScript 파일에는 `defer`를 사용한다.

`defer`가 필요한 정확한 실행 시점과 DOM 관계는 v0.4에서 본격적으로 다룬다.

또한 VS Code의 Live Server를 이용해 HTML 파일을 브라우저에서 실행하고 변경사항을 확인하는 기본 개발 흐름을 익힌다.

---

### 4.4 시맨틱 HTML

다음 태그의 의미를 구분한다.

- `header`
- `nav`
- `main`
- `section`
- `article`
- `footer`

핵심 질문은 다음과 같다.

> 이 태그가 화면에서 어떻게 보이는가?

가 아니라

> 이 콘텐츠는 문서에서 어떤 역할을 하는가?

이다.

---

### 4.5 제목 계층

`h1`부터 `h6`까지는 글자 크기를 선택하기 위한 태그가 아니라 문서의 제목 계층을 표현한다.

페이지 전체의 대표 제목과 각 section의 제목 사이에 논리적인 계층이 존재하도록 구성한다.

---

### 4.6 링크와 페이지 내부 이동

`a` 요소와 `href`의 역할을 이해한다.

특히 다음 관계를 이해한다.

```text
<a href="#contact">
        ↓
<section id="contact">
```

JavaScript 없이도 브라우저가 문서 내부 위치로 이동할 수 있다는 것을 확인한다.

또한 **이동을 위한 요소인 `a`와 동작을 실행하기 위한 `button`의 역할이 다르다**는 것을 이해한다.

Hero의 CTA가 다른 section으로 이동하는 기능이므로 이 버전에서는 `a` 요소를 사용한다.

---

### 4.7 이미지

`img`의 기본 구조와 다음 속성의 역할을 이해한다.

```text
src
alt
```

특히 `alt`가 단순한 부가 설명이 아니라 이미지가 전달하는 정보를 텍스트로 제공하기 위한 속성이라는 점을 이해한다.

이미지 파일을 `images/` 디렉터리에서 관리하고 HTML에서 상대 경로로 연결하는 방법도 확인한다.

---

### 4.8 리스트

여러 항목으로 이루어진 콘텐츠는 단순히 여러 개의 `div`로 만드는 대신 목록이라는 의미에 맞는 HTML 구조를 사용할 수 있음을 이해한다.

Skills와 Navigation에서 리스트가 적절한지 판단해 본다.

---

### 4.9 section과 article의 차이

`section`은 페이지 안에서 주제별 영역을 구분한다.

예:

```text
About
Skills
Projects
Contact
```

`article`은 그 자체로 하나의 독립된 콘텐츠 단위를 나타낼 수 있다.

이 프로젝트에서는 개별 Project를 `article`로 표현할 수 있다.

---

### 4.10 Form 기본 구조

다음 요소들의 관계를 이해한다.

```text
form
label
input
textarea
button
```

또한 다음 속성의 기본 역할을 이해한다.

```text
type
name
id
for
```

특히 `label`의 `for`와 입력 요소의 `id`가 어떻게 연결되는지 이해한다.

`required`를 포함한 validation 관련 속성과 JavaScript validation은 v0.6에서 다룬다.

실제 데이터 전송 방식도 아직 다루지 않는다.

---

### 4.11 id와 class의 역할

두 속성을 구분한다.

```text
id
→ 문서 안의 특정 대상을 식별

class
→ 여러 요소를 같은 범주로 묶음
```

이 단계에서는 이후 CSS와 JavaScript가 사용할 수 있다는 정도까지 이해한다.

구체적인 CSS 선택자와 `querySelector`는 각각 해당 버전에서 학습한다.

---

### 5.11 브라우저 확인

CSS가 사실상 없는 상태에서도 브라우저에서 다음 사항을 확인할 수 있어야 한다.

```text
페이지의 모든 콘텐츠를 읽을 수 있다.
각 section의 경계를 제목으로 파악할 수 있다.
Navigation으로 각 section에 이동할 수 있다.
Hero CTA로 해당 section에 이동할 수 있다.
프로필 이미지가 정상적으로 표시된다.
Form에 값을 입력할 수 있다.
```

화면이 보기 좋지 않은 것은 v0.1에서는 문제가 아니다.

### 5.12 이해 확인

3. `section`과 `article`은 어떻게 다른가?

7. `img`의 `alt`는 왜 필요한가?
8. 이미지 파일과 HTML 파일의 상대 경로는 어떤 관계인가?
9. `label`의 `for`와 `input`의 `id`는 어떻게 연결되는가?
10. `id`와 `class`는 어떻게 다른가?
11. HTML에서 CSS 파일과 JavaScript 파일을 어떻게 연결하는가?
12. Live Server는 현재 개발 과정에서 어떤 역할을 하는가?
13. 현재 HTML 구조가 이후 CSS와 JavaScript 작업의 기반이 되는 이유는 무엇인가?

이 질문에 자신의 말로 설명할 수 있으면 v0.1의 핵심 개념을 이해한 것으로 본다.

## 6. 이번 버전에서 다루지 않을 범위

다음 내용은 구현하지 않는다.

## 7. VS Code AI 작업 Task

v0.1에서도 한 번의 요청으로 전체 HTML을 생성시키지 않는다.

각 Task를 완료할 때마다 다음 절차를 따른다.

```text
diff 확인
→ 코드 확인
→ 브라우저 확인
→ 이해 확인
```

### Task 1 — 프로젝트 기본 파일 및 개발 환경 구성

VS Code AI에 요청할 범위:

```text
index.html
css/style.css
js/main.js
images/

기본 파일과 디렉터리를 만든다.

index.html에 CSS와 JavaScript를 연결한다.
JavaScript는 defer로 연결한다.

VS Code Live Server로 index.html을 실행하고,
파일 수정 시 브라우저에서 변경 내용이 반영되는지 확인한다.

페이지 콘텐츠나 스타일, JavaScript 기능은 아직 만들지 않는다.
```

확인할 개념:

- 파일과 디렉터리
- 상대 경로
- HTML / CSS / JavaScript 파일의 관계
- `link`
- `script`
- `defer`
- Live Server

---

### Task 2 — 페이지 최상위 구조

다음 구조만 만든다.

```text
header
main
footer
```

아직 개별 section의 상세 콘텐츠는 만들지 않는다.

확인할 개념:

- 시맨틱 HTML
- 부모 / 자식 관계
- 문서 구조

---

### Task 3 — Navigation과 section 골격

다음 section을 만든다.

```text
Hero
About
Skills
Projects
Contact
```

Navigation과 각 section의 `id`를 연결한다.

아직 각 section의 상세 콘텐츠는 최소화한다.

확인할 개념:

- `nav`
- `section`
- `id`
- `a`
- fragment link
- 제목 계층

---

### Task 4 — Hero / About / Skills 콘텐츠

세 section에 필요한 실제 콘텐츠 구조를 추가한다.

```text
Hero
About
Skills
```

Hero의 Projects / Contact CTA는 해당 section으로 이동하는 `a` 요소로 구성한다.

About의 프로필 이미지는 `images/` 디렉터리에서 불러온다.

확인할 개념:

- heading
- paragraph
- link와 button의 의미 차이
- image / src / alt
- 상대 경로
- list

---

### Task 5 — Projects 구조

Projects에 임시 프로젝트 하나를 만든다.

프로젝트는 `article`을 사용한다.

아직 카드 디자인이나 API 코드는 작성하지 않는다.

확인할 개념:

- `section`과 `article`의 차이
- 독립적인 콘텐츠 단위

---

### Task 6 — Contact Form 구조

다음 필드를 만든다.

```text
Name
Email
Message
Submit
```

각 `label`과 입력 요소가 `for-id` 관계로 올바르게 연결되도록 한다.

JavaScript validation, `required` 기반 validation 설계, 실제 전송은 구현하지 않는다.

확인할 개념:

- `form`
- `label`
- `input`
- `textarea`
- `button`
- `type`
- `name`
- `id`
- `for`

---

### Task 7 — Footer 및 전체 HTML 검증

Footer를 추가하고 전체 문서를 검토한다.

검토 대상:

```text
시맨틱 구조가 적절한가
제목 계층이 자연스러운가
Navigation 링크가 동작하는가
Hero CTA가 올바른 section으로 이동하는가
id가 중복되지 않는가
이미지 경로가 올바른가
이미지 alt가 적절한가
label과 input이 for-id로 연결되어 있는가
불필요한 div를 사용하지 않았는가
Live Server에서 정상적으로 실행되는가
CSS나 JavaScript 기능을 선행 구현하지 않았는가
```

이 Task에서는 새로운 기능을 추가하지 않는다.

```text
프로젝트 구조   완료
```
