# v0.4 — 기본 DOM 인터랙션

## 1. 버전 목표

v0.3까지 만든 반응형 정적 페이지에 JavaScript를 처음 연결하여 **사용자 이벤트가 DOM 변화를 만드는 기본 흐름**을 구현한다.

이 버전의 핵심 흐름은 다음과 같다.

```text
사용자 행동 또는 브라우저 이벤트
        ↓
JavaScript Event Handler
        ↓
DOM 확인 또는 변경
        ↓
화면 변화
```

v0.4가 끝나면 최소한 다음 관계를 설명할 수 있어야 한다.

```text
어떤 이벤트가 발생했는가
→ 어떤 함수가 실행되는가
→ 어떤 DOM 요소를 대상으로 하는가
→ 무엇이 변경되는가
→ 브라우저 화면에서는 어떻게 보이는가
```

이번 버전에서는 JavaScript의 기본적인 DOM 선택과 이벤트 처리를 익히는 데 집중한다.

아직 복잡한 상태 관리, `localStorage`, Form validation, API는 다루지 않는다.

---

## 2. 요구사항

### 2.1 JavaScript 파일 사용

v0.1에서 연결한 외부 JavaScript 파일을 사용한다.

프로젝트에서 실제 사용하는 파일명에 맞춰 다음과 같은 구조를 유지한다.

```text
js/
└── main.js 또는 script.js
```

HTML 내부의 다음 방식은 사용하지 않는다.

```html
onclick="..."
```

이벤트는 JavaScript 파일에서 `addEventListener()`를 사용하여 연결한다.

HTML의 `<script>`는 `defer` 방식으로 연결된 기존 구조를 유지한다.

---

### 2.2 변수 선언

JavaScript 변수는 기본적으로 다음을 사용한다.

```text
const
let
```

`var`는 사용하지 않는다.

기본 원칙:

```text
다시 다른 값을 대입하지 않을 변수
→ const

값 자체가 변경되어야 하는 변수
→ let
```

모든 변수를 `let`으로 작성하지 않는다.

---

### 2.3 DOM의 기본 의미

HTML 문서가 브라우저에서 DOM이라는 구조로 표현되고 JavaScript가 그 DOM을 선택하고 변경할 수 있다는 것을 이해한다.

기본 관계:

```text
HTML
        ↓
브라우저가 해석
        ↓
DOM Tree
        ↓
JavaScript가 DOM 요소 선택
        ↓
DOM 확인 / 변경
```

DOM 전체 API를 학습하지 않는다.

이번 프로젝트에서 실제 사용하는 범위만 다룬다.

---

### 2.4 DOM 요소 선택

최소한 다음을 사용한다.

```javascript
querySelector()
querySelectorAll()
```

차이를 이해한다.

```text
querySelector()
→ 조건에 맞는 첫 번째 요소

querySelectorAll()
→ 조건에 맞는 여러 요소
```

HTML에서 CSS 스타일링에 사용하는 class와 JavaScript에서 요소를 찾기 위한 class가 연결될 수 있음을 확인한다.

필요하면 JavaScript 동작을 식별하기 위한 class를 추가할 수 있다.

단, 기존 HTML의 의미 구조를 불필요하게 변경하지 않는다.

---

### 2.5 이벤트

JavaScript에서 브라우저의 특정 동작을 감지할 수 있다는 것을 이해한다.

이번 버전에서는 최소한 다음 이벤트를 다룬다.

```text
click
scroll
```

필요한 기능 안에서 이벤트가 발생하면 `addEventListener()`에 등록한 함수가 실행되는 구조를 확인한다.

---

### 2.6 Event Handler

이벤트가 발생했을 때 실행되는 함수의 역할을 이해한다.

기본 구조:

```text
이벤트 발생
        ↓
Event Handler 실행
        ↓
필요한 DOM 확인
        ↓
DOM 변경
```

함수 문법 전체를 별도 학습 과정으로 확대하지 않는다.

현재 이벤트 처리 코드를 읽고 설명할 수 있는 수준까지 다룬다.

---

### 2.7 `classList`

JavaScript가 HTML 요소의 class를 추가하거나 제거함으로써 CSS 상태를 바꿀 수 있다는 것을 이해한다.

이번 버전에서는 필요에 따라 다음을 사용한다.

```text
classList.add()
classList.remove()
classList.toggle()
```

핵심 관계:

```text
JavaScript
→ class 변경

CSS
→ 해당 class에 맞는 스타일 적용

화면
→ 표현 변화
```

JavaScript에서 직접 스타일 값을 반복해서 작성하는 방식보다 class를 통해 CSS와 연결하는 것을 기본 방식으로 삼는다.

---

### 2.8 모바일 햄버거 메뉴

v0.3에서 준비한 햄버거 버튼을 실제로 동작하게 만든다.

기본 흐름:

```text
사용자
→ Hamburger click

JavaScript
→ 메뉴 요소 선택
→ active class toggle

CSS
→ active 상태의 메뉴 표시

화면
→ 메뉴 열림 / 닫힘
```

핵심 동작은 다음 구조를 따른다.

```text
classList.toggle('active')
```

정확한 class 이름은 현재 HTML/CSS 구조에 맞춰 결정한다.

---

### 2.9 햄버거 메뉴와 Navigation 링크

모바일 메뉴가 열린 상태에서 Navigation 링크를 선택했을 때 필요하면 메뉴를 다시 닫는다.

흐름:

```text
Navigation link click
→ 해당 section으로 이동
→ 모바일 메뉴가 열려 있다면 닫음
```

이 기능이 현재 Navigation 구조에서 실제로 필요한지 브라우저에서 확인한 뒤 적용한다.

필요하지 않은 별도 상태 체계를 만들지는 않는다.

---

### 2.10 부드러운 내부 스크롤

Navigation과 Hero CTA를 이용하여 페이지 내부 section으로 이동할 때 부드럽게 이동하도록 한다.

주요 대상:

```text
Hero / Home
About
Skills
Projects
Contact
```

기본 흐름:

```text
내부 링크 click
        ↓
이동 대상 확인
        ↓
해당 section으로 이동
        ↓
부드러운 스크롤
```

JavaScript로 구현하는 경우 기본 앵커 이동과 JavaScript 제어의 관계를 이해한다.

정확한 API와 구현 방식은 Task에서 확인한다.

불필요하게 외부 라이브러리를 사용하지 않는다.

---

### 2.11 Scroll-to-Top 버튼

페이지를 일정 거리 이상 스크롤하면 Scroll-to-Top 버튼을 표시한다.

기본 흐름:

```text
사용자 scroll
        ↓
현재 scroll 위치 확인
        ↓
기준 이상
→ 버튼 표시

기준 미만
→ 버튼 숨김
```

버튼을 클릭하면 페이지 상단으로 이동한다.

```text
Scroll-to-Top click
        ↓
페이지 상단으로 이동
```

정확한 표시 기준값은 구현 과정에서 결정할 수 있다.

B1-1의 예시 기준값을 변경하는 경우 최종 README에서 기록할 수 있도록 해당 값을 인지하고 있어야 한다.

---

### 2.12 스크롤에 따른 Navigation 스타일 변경

사용자가 페이지를 일정 거리 이상 스크롤하면 Header 또는 Navigation의 시각적 상태를 변경한다.

예:

```text
페이지 상단
→ 기본 Navigation 스타일

일정 거리 이상 scroll
→ scrolled class 추가
→ 배경 / shadow 등 스타일 변화
```

기본 흐름:

```text
scroll 이벤트
        ↓
현재 scroll 위치 확인
        ↓
조건 판단
        ↓
class 추가 또는 제거
        ↓
CSS 표현 변경
```

정확한 기준값은 구현 단계에서 결정한다.

이 버전에서는 어떤 section이 현재 활성 상태인지 추적하는 기능까지 확대하지 않는다.

---

### 2.13 JavaScript와 CSS의 역할 구분

JavaScript에서 화면 스타일 전체를 직접 작성하지 않는다.

기본 역할은 다음처럼 구분한다.

```text
JavaScript
→ 이벤트 감지
→ 조건 판단
→ DOM 상태 변경

CSS
→ DOM 상태에 따른 시각 표현
```

예:

```text
JavaScript
→ .active 추가

CSS
→ .active일 때 메뉴 표시
```

이 구조를 햄버거 메뉴와 스크롤 Navigation에서 직접 확인한다.

---

### 2.14 반복되는 DOM 요소 처리

Navigation 링크처럼 여러 요소에 동일한 이벤트를 연결해야 하는 경우 `querySelectorAll()`로 요소들을 선택하고 반복 처리할 수 있다.

필요한 경우 다음을 사용한다.

```text
forEach()
```

`forEach()` 문법 전체를 별도로 깊게 학습하지 않는다.

현재 코드에서 다음 흐름을 이해하는 것이 목표다.

```text
여러 DOM 요소 선택
→ 각각에 같은 작업 적용
```

## 3. 목표 설계

v0.4 완료 시 웹사이트의 동작 구조는 다음과 같다.

```text
HTML 구조              ← v0.1
        ↓
CSS 기본 표현          ← v0.2
        ↓
반응형 레이아웃        ← v0.3
        ↓
JavaScript
        │
        ├── DOM 선택
        │
        ├── click 이벤트
        │       │
        │       ├── Hamburger
        │       ├── Navigation
        │       └── Scroll-to-Top
        │
        └── scroll 이벤트
                │
                ├── Scroll-to-Top 표시
                └── Navigation 스타일
```

사용자 관점에서는 다음 기능이 동작한다.

```text
모바일
│
├── Hamburger click
│   └── Navigation 열림 / 닫힘
│
├── Navigation / CTA click
│   └── section으로 부드럽게 이동
│
├── Scroll
│   ├── Navigation 스타일 변화
│   └── Scroll-to-Top 버튼 표시
│
└── Scroll-to-Top click
    └── 페이지 상단으로 이동
```

이 버전에서 처음으로 다음 기본 구조가 실제 코드에서 나타난다.

```text
Event
→ JavaScript
→ DOM 변경
→ 화면 변화
```

## 4. 새롭게 배우는 개념

### 4.1 JavaScript의 역할

현재 프로젝트에서 HTML, CSS, JavaScript의 역할을 다음처럼 구분한다.

```text
HTML
→ 무엇이 존재하는가

CSS
→ 어떻게 보이는가 / 어떻게 배치되는가

JavaScript
→ 무엇이 일어났을 때 어떻게 반응하는가
```

---

### 4.2 DOM

DOM은 브라우저가 HTML 문서를 JavaScript에서 다룰 수 있는 구조로 표현한 것이라는 수준에서 이해한다.

HTML 파일 자체를 직접 수정하는 것이 아니라 실행 중인 브라우저의 DOM을 JavaScript가 변경한다는 점을 이해한다.

---

### 4.3 DOM Tree와 부모 / 자식 관계

v0.1에서 학습한 HTML의 부모 / 자식 구조가 DOM에서도 연결된다는 것을 확인한다.

DOM Tree 전체 API를 암기하지 않는다.

---

### 4.4 `querySelector()`

CSS selector와 비슷한 방식으로 DOM 요소를 찾을 수 있다는 것을 이해한다.

예:

```javascript
document.querySelector('.menu-toggle')
```

이를 다음처럼 읽을 수 있어야 한다.

```text
document에서
.menu-toggle에 해당하는 첫 번째 요소를 찾는다.
```

---

### 4.5 `querySelectorAll()`

조건에 맞는 여러 DOM 요소를 선택할 수 있다는 것을 이해한다.

Navigation 링크처럼 같은 처리가 필요한 여러 요소에서 사용한다.

---

### 4.6 `const`와 `let`

값을 다시 대입할 필요가 있는지에 따라 두 선언 방식을 구분한다.

이 단계에서는 scope, hoisting 등의 JavaScript 언어 이론으로 학습 범위를 확대하지 않는다.

---

### 4.7 Event

브라우저에서 발생하는 사용자 행동이나 상태 변화가 JavaScript가 반응할 수 있는 사건이라는 것을 이해한다.

이번 단계의 대표 이벤트:

```text
click
scroll
```

---

### 4.8 `addEventListener()`

특정 요소 또는 브라우저 객체에 이벤트가 발생했을 때 실행할 함수를 연결한다는 것을 이해한다.

다음 관계를 읽을 수 있어야 한다.

```text
대상
.addEventListener(
    이벤트 종류,
    실행할 함수
)
```

---

### 4.9 Event Handler

이벤트가 발생했을 때 실행되는 코드라는 것을 이해한다.

중요한 것은 함수 이름이나 문법보다 다음 관계다.

```text
무슨 이벤트인가
→ 어떤 handler가 실행되는가
→ handler가 무엇을 변경하는가
```

---

### 4.10 `classList`

DOM 요소의 class를 JavaScript로 변경할 수 있다는 것을 이해한다.

```text
add
→ class 추가

remove
→ class 제거

toggle
→ 있으면 제거 / 없으면 추가
```

---

### 4.11 상태 표현으로서의 class

이번 버전에서는 별도의 복잡한 JavaScript 상태 객체를 만들지 않지만 class가 현재 UI 상태를 나타낼 수 있다는 것을 경험한다.

예:

```text
Navigation

active 없음
→ 닫힌 상태

active 있음
→ 열린 상태
```

이 경험은 이후 v0.5의 명시적인 theme 상태 학습으로 이어진다.

---

### 4.12 조건문

스크롤 위치처럼 조건에 따라 다른 동작이 필요한 경우 조건문을 사용한다.

기본 관계:

```text
조건 확인

참
→ A 실행

거짓
→ B 실행
```

JavaScript 조건문 전체 문법을 장기간 별도로 학습하지 않는다.

현재 기능에서 왜 조건이 필요한지 설명할 수 있으면 된다.

---

### 4.13 Scroll Position

현재 페이지가 얼마나 스크롤되었는지 JavaScript에서 확인할 수 있다는 것을 이해한다.

이 값은 다음 기능의 입력으로 사용된다.

```text
Navigation 스타일 변화
Scroll-to-Top 표시 여부
```

정확한 브라우저 API의 이름과 사용법은 구현 과정에서 코드와 함께 확인한다.

---

### 4.14 DOM 상태와 CSS의 연결

다음 구조를 실제 코드에서 이해한다.

```text
JavaScript
→ class 추가

DOM
→ class 상태 변경

CSS
→ 새 class 규칙 적용

화면
→ 시각적 변화
```

이번 버전에서 가장 중요한 구조 중 하나다.

---

### 4.15 `forEach()`

여러 요소에 같은 작업을 반복 적용할 때 사용할 수 있음을 이해한다.

예:

```text
Navigation links
→ 각각 click listener 연결
```

배열 메서드 전체 학습으로 확대하지 않는다.

---

### 4.16 기본 앵커 동작과 JavaScript 제어

v0.1에서는 `<a href="#projects">`만으로도 내부 이동이 가능했다.

v0.4에서는 JavaScript를 이용해 그 동작을 보완하거나 제어할 수 있음을 확인한다.

따라서 다음 차이를 이해한다.

```text
HTML 기본 기능
→ JavaScript 없이도 이동 가능

JavaScript
→ 사용자 경험이나 추가 동작 제어
```

HTML이 제공하는 기본 기능을 불필요하게 JavaScript로 다시 만드는 것이 목적은 아니다.

---

### 4.17 브라우저 DevTools Console

JavaScript 오류가 발생하면 브라우저 Console에서 확인한다.

최소한 다음을 할 수 있어야 한다.

```text
오류 발생 여부 확인
오류가 발생한 파일 확인
대략적인 코드 위치 확인
```

JavaScript가 동작하지 않을 때 바로 전체 코드를 다시 생성하지 않는다.

---

## 5. 완료 / 검증 기준

### 5.1 JavaScript 연결

외부 JavaScript 파일이 정상적으로 로드된다.

HTML에 inline event handler가 없다.

예:

```text
onclick
onscroll
```

이벤트는 `addEventListener()`로 연결되어 있다.

---

### 5.2 변수

JavaScript에서 `const`와 필요한 경우 `let`을 사용한다.

`var`를 사용하지 않는다.

---

### 5.3 DOM 선택

실제 기능에서 `querySelector()` 또는 `querySelectorAll()`을 사용한다.

선택한 요소가 HTML의 어떤 요소인지 설명할 수 있다.

---

### 5.4 햄버거 메뉴

모바일 화면에서 다음을 확인한다.

```text
Hamburger 표시

click
→ 메뉴 열림

다시 click
→ 메뉴 닫힘
```

이 동작이 `classList`와 CSS를 통해 연결되어 있다.

---

### 5.5 Navigation 링크

Navigation 및 CTA를 이용한 페이지 내부 이동이 정상 동작한다.

부드러운 스크롤을 적용했다면 각 section까지 자연스럽게 이동한다.

기존 앵커 링크의 의미 구조가 깨지지 않는다.

---

### 5.6 Scroll-to-Top

페이지 상단에서는 버튼이 숨겨져 있다.

일정 거리 이상 스크롤하면 버튼이 보인다.

버튼을 누르면 페이지 상단으로 이동한다.

---

### 5.7 Navigation 스크롤 스타일

페이지 상단과 일정 거리 이상 스크롤한 상태에서 Header 또는 Navigation의 시각적 표현이 구분된다.

JavaScript에서 class를 변경하고 CSS가 실제 표현을 담당한다.

---

### 5.8 Scroll 이벤트

하나의 scroll 동작이 어떤 JavaScript 코드로 전달되는지 설명할 수 있다.

같은 scroll 이벤트에서 여러 기능을 확인하는 구조라면 각각의 역할을 구분할 수 있어야 한다.

---

### 5.9 CSS / JavaScript 역할 분리

JavaScript에서 불필요하게 다음과 같은 직접 스타일 조작을 반복하지 않는다.

```text
element.style...
```

현재 기능에 특별한 이유가 없다면 class 변경을 기본 방식으로 사용한다.

CSS가 시각 표현을 담당한다.

---

### 5.10 모바일 검증

DevTools Responsive Mode에서 다음을 확인한다.

```text
햄버거 버튼이 보이는가
클릭하면 메뉴가 열리는가
다시 클릭하면 닫히는가
Navigation 링크가 동작하는가
메뉴 때문에 레이아웃이 깨지지 않는가
```

---

### 5.11 데스크톱 검증

큰 화면에서는 일반 Navigation이 정상적으로 보인다.

햄버거 메뉴용 JavaScript 때문에 데스크톱 Navigation이 깨지지 않는다.

---

### 5.12 스크롤 검증

페이지를 실제로 위아래로 이동하며 확인한다.

```text
Navigation 스타일 변화
Scroll-to-Top 표시 / 숨김
Scroll-to-Top click
내부 링크 이동
```

한 위치에서만 확인하지 않는다.

---

### 5.13 Console 확인

브라우저 Console에 현재 구현 때문에 발생하는 JavaScript 오류가 없어야 한다.

## 7. VS Code AI 작업 Task

### Task 1 — JavaScript 연결 확인과 DOM 선택

새로운 UI 기능을 한꺼번에 만들지 않는다.

기존 JavaScript 파일이 정상 연결되었는지 확인하고 필요한 DOM 요소 몇 개를 선택한다.

- `defer`
- DOM
- `document`
- `querySelector`
- `querySelectorAll`
- `const`

브라우저 Console에서도 JavaScript 오류가 없는지 확인한다.

---

### Task 2 — 햄버거 메뉴 click

모바일 햄버거 버튼 하나의 동작만 구현한다.

흐름:

```text
Hamburger 선택
Navigation menu 선택
        ↓
click listener
        ↓
classList.toggle()
        ↓
메뉴 표시 / 숨김
```

아직 다른 scroll 기능은 추가하지 않는다.

확인할 개념:

- `click`
- `addEventListener`
- Event Handler
- `classList.toggle`
- JavaScript와 CSS 역할 분리

---

### Task 3 — 모바일 Navigation 링크 처리

필요한 경우 모바일 Navigation 링크를 선택하고 메뉴가 열린 상태에서 링크를 누르면 메뉴를 닫는다.

확인할 개념:

- `querySelectorAll`
- 여러 DOM 요소
- `forEach`
- 동일 이벤트 반복 연결
- `classList.remove`

새로운 기능이 실제 사용성에 필요하지 않다면 불필요하게 복잡하게 만들지 않는다.

---

### Task 4 — 내부 링크 부드러운 스크롤

Navigation과 Hero CTA의 내부 이동을 확인한다.

필요한 방식으로 부드러운 스크롤을 적용한다.

확인할 개념:

- 앵커 링크
- click event
- 이동 대상 DOM
- 브라우저 기본 동작과 JavaScript 제어

햄버거 메뉴와 무관한 다른 스크롤 기능은 아직 추가하지 않는다.

---

### Task 5 — Scroll-to-Top 표시

Scroll-to-Top 버튼 구조가 없다면 필요한 최소 HTML을 추가한다.

먼저 scroll 위치에 따라 버튼이 표시되거나 숨겨지는 동작만 구현한다.

```text
scroll
→ 위치 확인
→ class 추가 / 제거
```

아직 click 시 상단 이동은 다음 Task로 분리한다.

확인할 개념:

- `scroll`
- 현재 scroll 위치
- 조건문
- `classList.add`
- `classList.remove`

---

### Task 6 — Scroll-to-Top click

버튼을 눌렀을 때 페이지 상단으로 이동하도록 한다.

확인할 개념:

- `click`
- 브라우저 스크롤 제어
- 이벤트와 화면 변화

---

### Task 7 — Navigation scroll 스타일

일정 거리 이상 스크롤했을 때 Header 또는 Navigation에 상태 class를 추가하고, 상단으로 돌아오면 제거한다.

CSS에서 해당 class의 시각적 스타일을 정의한다.

확인할 개념:

- 같은 scroll 정보를 다른 UI에도 활용
- 조건문
- `classList.add/remove`
- JavaScript 상태 변화와 CSS 표현 연결

Scroll-to-Top click이 정상인가
